# 20261031-05 gplat 去掉 master/worker：改为单进程多线程，信号改用 signalfd

来源：[261031-02](261031-02.md) 第六节第 2 条“worker 崩溃即全站下线”，以及对 master/worker 设计本身是否合理的评估。

## 一、为什么去掉 master/worker

nginx 采用 master/worker 的理由，在 gPlat 里都不成立：

| nginx 的理由 | gPlat 的实际情况 |
|---|---|
| 多个 worker 用满多核 | `WorkerProcesses` 只能是 1：订阅表、待发队列、请求通道都在 worker 自己的内存里，Board 的锁是非进程共享的 `std::mutex`。多核本来就由线程池利用 |
| worker 崩溃后由 master 拉起 | master 收到 SIGCHLD 就自己退出，不重启 worker |
| 平滑 reload、热升级 | 没有实现，SIGHUP 只记一行日志 |
| 特权分离 | 监听 8777，代码里没有 `setuid` |

master 实际只做三件事：fork worker、`sigsuspend` 等信号、经 socketpair 通知 worker 退出。它带来的复杂度却已经引出过一串问题：

| 问题 | 来源 |
|---|---|
| worker 继承 SIGCHLD 处理函数，`waitpid(-1)` 抢走 ASan tracer 的状态，worker 退出卡死 | `6adcafa` |
| 给单线程 master 写的信号处理函数被多线程 worker 继承，信号落在持有日志锁的线程上自死锁 | 261031-02 E3 |
| 重复 SIGTERM 对已被复用的 socketpair fd 号 write/close | 261031-02 E4 |
| epoll 的 `data.fd` / `data.ptr` 联合体误读 | 261031-02 H1 |
| 两个进程各自持有日志状态、各自轮转（见下） | 本次实测 |
| 测试夹具要扫 `/proc` 找 worker，套件要 `PR_SET_CHILD_SUBREAPER` 收养孤儿 | — |

### 新发现：master 与 worker 日志轮转互相干扰

`ngx_log_rotate()` 在两个进程里各有一份状态。沙箱实测（`LogRotateFileSize = 1`）：

1. worker 把日志撑过阈值后轮转，`gplat.log` → `gplat.log.1`，新建 `gplat.log`。
2. master 手里的 fd 仍指向已改名的 `.1`，该文件已超过阈值。
3. master 收到 SIGTERM 写日志时再轮转一次，把 worker 正在写的 `gplat.log` 改名成 `.1`，`.1` 变 `.2`。

结果：`gplat.log` 只剩 master 的停机日志，worker 的最后几行和整段停机日志落在 `.1`，启动日志被挤到 `.2`；备份已满时还会提前删掉最旧的一份。单进程后只有一份日志状态，问题消失。

### 对“在 master 中重启 worker”的结论

261031-02 建议“在 master 中重启 worker（Board 锁在 `LoadQ` 时重新构造，重启是安全的）”。在旧代码下这并不成立：`LoadQ` 只在 master fork 之前调用一次，新 worker 继承同一个 `MAP_SHARED` 映射。旧 worker 崩溃时若持有某个 stripe 锁，这把锁仍是锁住的，新 worker 第一次访问该 stripe 就会死锁。要让它安全就得把 `LoadQ` 挪进 worker，那样 master 就只剩“拉起子进程”，这正是 systemd 的工作。整个进程重启会重新执行 `LoadQ`、重建全部锁，是安全的。

worker 重启本来就会丢掉订阅、待发事件和连接，客户端都得重连，对客户端而言与整个进程重启没有区别。

## 二、新的进程结构

```
main()
  配置 → 日志 → LoadQ → 监听端口
  → (Daemon=1) ngx_daemon()           此时还没有线程，fork 安全
  → ngx_init_signals()                屏蔽信号 + signalfd，必须在创建线程之前
  → ngx_single_process_cycle()
       ngx_threads_init()             线程池、定时器线程及 5 个周期定时器、发送/回收线程、epoll
       主线程 epoll 循环 ……直到 g_stopEvent
       g_tm.stop() → g_threadpool.StopAll() → g_socket.Shutdown_subproc()
```

主线程 + 辅助线程：线程池（`ProcMsgRecvWorkThreadCount`）、发送线程、回收线程、定时器线程。实测前台启动共 6 个线程（主线程 + 2 个池线程 + 发送 + 回收 + 定时器）。

### 信号：从处理函数改为 signalfd

- 旧模型的核心隐患：处理函数里写日志要取 `log_mutex`（非递归），信号落在持锁线程上就自死锁。单进程里所有线程都是“worker 线程”，更不能保留处理函数。
- `ngx_init_signals()`（[ngx_signal.cxx](../../gplat/ngx_signal.cxx)）：
  - 忽略：SIGPIPE、SIGSYS、SIGUSR1、SIGUSR2、SIGALRM、SIGIO、SIGWINCH（默认动作会杀死进程，或没有意义）。
  - 用 `pthread_sigmask` 屏蔽 SIGINT、SIGTERM、SIGHUP、SIGQUIT，并 `signalfd(SFD_NONBLOCK | SFD_CLOEXEC)`。必须在创建任何线程之前调用，线程才会继承屏蔽字，这些信号就只会经 signalfd 到达。
- signalfd 以 `data.ptr == nullptr` 注册进 epoll，取代原来 `sockpair[0]` 的位置（连接事件的 `data.ptr` 非空，这个标记延续 H1 的修法）。
- `ngx_handle_signals()` 在 epoll 线程（即主线程）里循环读到 `EAGAIN`：
  - SIGINT / SIGTERM：记日志并置 `g_stopEvent`；epoll 循环返回后主循环退出。
  - SIGHUP / SIGQUIT：只记日志，与原行为一致（没有 reload 功能，终端断开也不退出）。
- 读信号发生在普通线程上下文，日志、锁都可以安全使用，E3、E4 这类问题从根上不会再出现。重复信号无副作用（不再有 fd 可被重复关闭）。

### 守护进程化与 systemd

- `Daemon=1` 仍可用：`ngx_daemon()` 在创建任何线程之前 fork，子进程就是唯一服务进程。实测新会话、6 个线程、原父进程退出码 0。
- 由 systemd 托管时用 `Daemon = 0`。新增 [Doc/gplat.service](../gplat.service)：`Type=simple`、`Restart=always`、`TimeoutStopSec=15`、`LimitNOFILE=65536`。进程崩溃或挂死被 systemd 拉起，重启会重新 `LoadQ`、重建锁。

### 配置

- `WorkerProcesses` 从 [gplat.conf](../../config/gplat.conf) 删除，保留兼容：旧配置里写了不等于 1 的值，启动时记一条 `[warn]` 并忽略。
- `worker_connections`（epoll 连接数上限）名称不变。

## 三、删除与改名

| 删除 | 说明 |
|---|---|
| `ngx_master_process_cycle`、`ngx_start_worker_processes`、`ngx_spawn_process`、`ngx_worker_process_cycle` | master 循环和 fork |
| SIGCHLD 处理、`ngx_process_get_status`、`waitpid` | 没有子进程 |
| `sockpair`、`ngx_notify_workers_exit` | 退出改走 signalfd |
| `ngx_process`、`NGX_PROCESS_MASTER/WORKER`、`ngx_reap`、`ngx_parent`、`g_stopEventMain`、`g_daemonized` | 不再有进程角色 |
| `ngx_setproctitle.cxx`、`g_argvneedmem`、`g_envneedmem`、`g_os_argc/argv`、`gp_envmem` | 改进程标题和环境变量搬家只为 `ps` 里区分 master/worker |
| `ngx_signal_handler`、信号表 | 改用 signalfd |

改名：`g_stopEventChild` → `g_stopEvent`（原子；主线程置位，发送/回收线程轮询）；`ngx_worker_process_init` → `ngx_threads_init`；`ngx_worker_process_cycle` 的循环与停机并入 `ngx_single_process_cycle`。线程创建顺序、5 个定时器、退出顺序（定时器 → 线程池 → socket）均原样保留。

## 四、测试夹具

- `ServerFixture` 不再扫 `/proc` 找 worker：删除 `find_child_of`、`workerPid_`、`reap_worker`，`masterPid_` 改为 `pid_`，`reap_master()` 改为 `reap()`；`worker_pid()` / `master_pid()` 合并为 `server_pid()`，6 个测试文件的调用同步。
- 停机：向 gplat 发 SIGTERM，等待 8 秒，超时 SIGKILL；`kill9()` 直接 SIGKILL。
- 测试配置不再写 `WorkerProcesses`。`PR_SET_CHILD_SUBREAPER` 保留（无害），注释改为准确描述。

## 五、行为变化与注意事项

- 线协议、锁顺序、业务逻辑不变。
- `ps` 里进程名就是 `gplat`，不再是 `gplat master` / `gplat worker`；按进程名匹配的运维脚本需要调整（仓库内未发现此类脚本）。
- gplat 崩溃后不再有 master 兜底，需要 systemd 等外部守护；这是单进程方案的取舍，换来的是更少的故障面和更简单的排查（gdb / perf / ASan / TSan 不必再跟踪 fork 出的子进程，崩溃原因在 `journalctl` / `coredumpctl`）。
- 重启的一两秒内端口关闭，客户端按 CONNECTION 类错误重连即可。
- 不在本次范围：多进程水平扩展（需要先把订阅表等状态放进共享内存，属于另一个量级的设计）。

- `make`：干净构建，无新增警告。
- `make test`：74 passed / 0 failed / 3 skipped（ASan 专用），另有 28 个破坏性 / 压力用例默认隐藏。
- `make test-all`（ASan，含破坏性 / 压力，共 105 个用例）：**105 passed / 0 failed / 0 skipped**，覆盖退出顺序、定时器、连接回收、信号相关用例。
- 沙箱手动验证（独立端口、临时目录，用后删除）：
  - 前台：6 个线程；SIGUSR1 被忽略，SIGHUP 只记 `ignored`，服务不退出；SIGTERM 后日志依次为“主线程跳出无限循环 → `CThreadPool::StopAll()` → `CSocekt::Shutdown_subproc()` → 程序退出”，进程退出码 0。
  - `Daemon=1`：新会话单进程、6 个线程；SIGTERM 优雅退出。
  - 配置 `WorkerProcesses = 4`：日志出现废弃警告，服务正常。
