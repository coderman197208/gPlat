# 260930-03 higplat.h 改为纯 C 头文件，GplatConnection 作为其 C++ 封装

## 1. 问题

原 `extern "C"` 接口中含有 `std::string`（`readb_string2`、`writeb_string2`、`waitpostdata`、`write_plc_string`），这并不是纯 C ABI：

- **ABI 不匹配时编译期发现不了**：普通 C++ 函数的修饰名里带有 libstdc++ 的 ABI 标记（`__cxx11`），`_GLIBCXX_USE_CXX11_ABI` 不一致时链接直接报错。`extern "C"` 去掉了名字修饰，不一致时照样能链接，运行时才出现堆损坏或崩溃。
- C、Python ctypes、C#、Go cgo 等无法调用这几个函数，而其中 `waitpostdata` 恰好是订阅的核心接口。
- `std::string` 在库内分配、在调用方释放，只有两边共用同一个 `libstdc++.so` 时才安全。
- 此外，C 接口会抛 C++ 异常（`error == nullptr`、`AutoErrorCheck` 对 Fatal 级错误抛 `runtime_error`、`std::filesystem` 抛异常），异常穿过 C 调用方会直接 `std::terminate`。
- 头文件里的默认参数、`=delete` 模板和 `read_value` 使它只能被 C++ 使用。

## 2. 方案确认

分层原则：`include/higplat.h` 是 `libhigplat.so` 的纯 C 头文件；`include/gplat_connection.h` 是它的 C++ 封装，`std::string`、异常、默认参数等 C++ 特性只存在于调用方的编译单元。

| 问题 | 决定 |
|---|---|
| 异常 | C 层不抛异常：`error` 为空时返回 false；Fatal 只打印日志。由 `GplatConnection` 通过 `IsFatalError` 判断后抛 `std::runtime_error` |
| 已有调用方 | 就地改用新的 C 签名；`read_value` 移到 `gplat_connection.h`，用到它的 testapp 改为包含该头文件 |
| string 相关函数 | 函数名不变、只改签名：`waitpostdata` 的 tagname 改为 `char*` 加长度，`write_plc_string` 改为 `const char*`；删除 `readb_string2` / `writeb_string2`，由 `GplatConnection` 的 `std::string` 重载基于 `readb_string` / `writeb_string` 实现 |

## 3. 实现

### 3.1 `include/higplat.h`

- 头文件只包含 `<stdbool.h>` 和 `<time.h>`，另加 `struct timespec;` 前置声明，C99 严格模式下也不会告警。
- 声明放在 `#ifdef __cplusplus extern "C" { ... }` 块中，去掉每行的 `extern "C"`。
- `QUEUE_HEAD` / `RECORD_HEAD` / `BOARD_INFO` / `TAG_META` 改为 `typedef struct X {...} X;`。
- 去掉全部默认参数（`readb`、`readb_string`、`getresponse`、`CreateItem`、`CreateQ`、`ReadQ`、`WriteQ`、`ReadB`、`ReadB_String`、`WriteB`、`WriteB_String`）。
- 去掉 `write_plc_*` 的 `=delete` 模板（`GplatConnection` 中已有）和 `read_value`。
- `timespec*` 改为 `struct timespec*`；`ReadB_String2` 的 `int& strLength` 改为 `int*`；`GetLastErrorQ()` 改为 `GetLastErrorQ(void)`。
- 新增：
  - `GPLAT_MAX_DATA_SIZE`（16384）：单次读写数据的最大长度
  - `GPLAT_TAGNAME_SIZE`（40）：tag 名缓冲区长度（含 `'\0'`）
  - `bool IsFatalError(unsigned int error, const char** message)`
- 签名变化：

| 函数 | 原签名 | 新签名 |
|---|---|---|
| `waitpostdata` | `(int, std::string& tagname, void*, int, int, unsigned int*)` | `(int, char* tagname, int tagnamesize, void*, int, int, unsigned int*)`，`tagnamesize < GPLAT_TAGNAME_SIZE` 时返回 `ERROR_INVALID_PARAMETER` |
| `write_plc_string` | `(int, const char*, std::string, unsigned int*)` | `(int, const char*, const char*, unsigned int*)` |
| `readb_string2` / `writeb_string2` | — | 删除 |

### 3.2 `higplat/higplat.cpp` 与 `higplat/qbd.h`

- `qbd.h` 改为包含 `higplat.h`，删除其中重复的错误码、模式 / PEEK 宏和四个结构体。这样编译器会用头文件检查 `higplat.cpp` 中的定义（此前两者互不可见，签名不一致也发现不了）。并加入 `static_assert(MAXDQNAMELENTH == GPLAT_TAGNAME_SIZE)`。
- `higplat.cpp` 中新增 `static_assert`：`GPLAT_MAX_DATA_SIZE == MAXMSGLEN`、`GPLAT_TAGNAME_SIZE == sizeof(MSGHEAD::itemname)`。
- 改为包含头文件后，编译立即发现一处真实的不一致：`readtype` 的实现参数为 `char*`，而头文件声明为 `const char*`。已修正，同时修复了原来 `!error` 分支中对空指针 `*error` 赋值的问题。
- 所有 `throw std::runtime_error("parameter error is null")` 改为 `return false`。
- `AutoErrorCheck` 析构函数去掉 `noexcept(false)` 和 throw，Fatal 级错误只打印日志。
- `CreateQ` / `CreateB` 中的 `fs::exists` / `fs::remove` / `fs::create_directories` 改用 `std::error_code` 重载。
- 新增 `IsFatalError`（基于 `GetErrorInfo`）。
- 删除 `readb_string2` / `writeb_string2`；`waitpostdata` 改为写入 `char*`（超时时写入 `"WAIT_TIMEOUT"`）；`write_plc_string` 直接传 `const char*`；`ReadB_String2` 改为 `*strLength = ...`。

### 3.3 `include/gplat_connection.h`

- 加入 `read_value<T>` 模板（从 `higplat.h` 移入）。
- `readb_string(tag, std::string&, timespec*)`：用 `GPLAT_MAX_DATA_SIZE` 大小的临时缓冲区调用 C 版 `readb_string`，成功时才赋值给 `value`（与原 `readb_string2` 一致，失败时不修改）。
- `writeb_string(tag, const std::string&)`：转调 `writeb_string(tag, value.c_str())`。
- `waitpostdata(std::string& tagname, ...)`：内部用 `char name[GPLAT_TAGNAME_SIZE]` 调用 C 函数，调用后赋值给 `tagname`。
- `write_plc_string`：传入 `str.c_str()`。
- `call()`：去掉 `try/catch`（C 层已不抛异常）。执行顺序改为：调用 → 按 `closed_by_library` 更新连接状态 → 若 `IsFatalError(error)` 则抛出 `std::runtime_error("<message> (Code: N)")` → 返回错误码。对 `GplatConnection` 的使用者来说，行为与之前相同。

## 5. 注意事项

- **已有二进制需要重新编译**：`waitpostdata`、`write_plc_string` 名字不变但签名改变，旧二进制仍能链接成功，运行时会出错。本仓库内的程序已全部重新编译。
- 直接调用 C 接口的 C++ 程序（toolgplat、s7ioserver、testapp1~5）在 Fatal 错误时不再收到异常，只得到 `false` 和错误码。需要异常语义的应使用 `GplatConnection`。
- `libhigplat.so` 仍以 C++ 修饰名导出若干内部辅助函数（`writeb_`、`readn`、`fetchtab` 等），这些函数不在头文件中，不影响 C 接口，隐藏它们可作为后续清理项。

结论：这确实不太规范，有实际的坏处。但如果所有调用方都是同一套 g++/libstdc++ 编译的 C++ 程序，眼下出问题的概率不高，所以不必急着删掉 `std::string` 接口。更合适的做法是把导出层改成纯 `char*`，`std::string` 的便利版本移到头文件里。

## 坏处

1. **ABI 不一致时链接器发现不了，只会在运行时崩溃。** 这是最主要的风险。
   - 正常的 C++ 函数，名字修饰里会带上 ABI 信息。新 ABI 的 `std::string&` 会修饰成 `NSt7__cxx1112basic_string...`，和旧 ABI 不一样。库和调用方的 `_GLIBCXX_USE_CXX11_ABI` 不同时，链接直接报 undefined symbol，问题在编译期就暴露。
   - `extern "C"` 去掉了名字修饰，符号就是 `waitpostdata`。ABI 不一致时照样能链接成功，运行时却把 32 字节的新版 string 当成 8 字节的 COW 指针来用，结果是堆损坏或段错误。
   - 也就是说，`extern "C"` 在这里去掉了一道安全检查，没带来任何好处。
2. **其他语言调不了。** Python ctypes、C#、Go cgo、纯 C 都无法构造 `std::string`。这 4 个函数正好是订阅主流程（`waitpostdata`）和字符串读写，是最常用的那部分。
3. **内存跨模块分配和释放。** `readb_string2`、`waitpostdata` 在库里给调用方的 string 分配内存，由调用方释放。Linux 下两边共用同一个 `libstdc++.so` 时没问题；静态链接 libstdc++，或者以后移植到 Windows（不同的 MSVC CRT），就会出错。
4. **按值传 `std::string`。** `writeb_string2` 和 `write_plc_string` 按值传入，每次调用多一次拷贝。而且按值传递非平凡对象，本身就依赖 C++ 的调用约定（Itanium ABI 会隐式改成传引用），和 C 语义不一致。

头文件里的默认参数、`= delete` 模板重载、`#include <string>` 也说明这个头文件只能给 C++ 用。不过这几项只影响头文件本身（默认参数是在调用方展开的），不影响二进制 ABI，危害比上面四点小得多。

## 要不要改成 `char*`

建议改，但不要硬替换。做法是分成两层：

- **导出层（`libhigplat.so`）只用纯 C 类型。** 例如：
  ```cpp
  extern "C" bool waitpostdata_c(int sockfd, char* tagname, int tagname_size,
                                 void* value, int buffersize, int timeout, unsigned int* error);
  extern "C" bool readb_string_len(int sockfd, const char* tagname, char* value,
                                   int buffersize, int* strlen_out, unsigned int* error, timespec* ts);
  extern "C" bool write_plc_string_c(int sockfd, const char* tagname, const char* str, unsigned int* error);
  ```
- **`std::string` 版本改成头文件里的 inline 函数（或者放进 `GplatConnection`）。** inline 代码在调用方自己的编译单元里展开，用的是调用方的 ABI，不会出现两边 ABI 不一致的问题。这和现在 `gplat_connection.h` "纯头文件、不导出 C++ 符号"的设计方向一致。

## 兼容性

- 调用点主要是 `waitpostdata`，在 s7ioserver、toolgplat、testapp1~6 里都有。如果 inline 版本沿用原来的函数名和签名，这些调用的源码可以不改。
- 但 inline 版本和导出符号不能同名，所以已编译的旧二进制会链接不到原来的符号。两种处理方式：
  - 全部重新编译（都在这个仓库里，成本很低）；
  - 在 `.so` 里把旧的导出符号保留一段时间，标成 deprecated。

目前的状态：本项目所有调用方都用同一个 Makefile、同一个编译器构建，暂时没有实际问题。需要改的时机是：要支持其他语言绑定、要交付给外部团队或第三方编译器，或者要移植到 Windows。
