# 260930-02 C 接口的 C++ 封装类（GplatConnection）

需求来源：[Doc/tasks/20260930-02.md](../tasks/20260930-02.md)

## 1. 需求要点

- `include/higplat.h` 的网络接口都是 `extern "C"`，现在提供一个 C++ 封装类 `GplatConnection`。
- 构造函数传入 gplat 服务的 IP 地址和端口；提供 `is_open()` / `open()` / `close()`。
- 把列出的 C 接口转换为成员方法，并做以下变动：
  1. 用函数重载取消 `readb_string2` / `writeb_string2`，统一为 `readb_string` / `writeb_string`；
  2. 取消 `unsigned int* error` 参数，改为方法的返回值；
  3. 取消 `int sockfd` 参数。
- 需考虑类的二进制兼容问题。

## 2. 方案确认（两轮提问）

| 问题 | 决定 |
|---|---|
| 实现方式与二进制兼容 | 只写头文件 `include/gplat_connection.h`，全部 inline 调用现有 `extern "C"` 接口。`libhigplat.so` 不新增 C++ 导出符号，库的 ABI 不变；类布局变化只需用户重新编译。现有 C 接口本身已含 `std::string&` 参数，已与 libstdc++ 的双 ABI 绑定，封装类没有引入新的依赖 |
| C 库内部 `close(sockfd)` | 不改 C 库，封装类按错误码判断连接是否已被关闭（规则见 3.2） |
| 未连接 / 已断开时调用 | 直接返回 `ERROR_SOCKET_NOT_CONNECTED`，不自动重连（重连会丢失服务端的订阅） |
| `open()` | 返回 `bool`，已打开时直接返回 `true`；构造函数只保存地址不连接；析构时自动 `close()` |
| 返回值 | `[[nodiscard]] unsigned int`，0 表示成功 |
| `waitpostdata` 超时 | 返回 `ERROR_WAIT_TIMEOUT`，`tagname` 仍置为 `"WAIT_TIMEOUT"` |
| 异常 | C 库对 Fatal 级错误抛出的 `std::runtime_error` 原样抛出，抛出前先更新连接状态 |
| 线程安全 | 不加锁，一个连接只能在一个线程中使用 |
| 参数类型 | 名称参数为 `const std::string&`；写入缓冲区为 `const void*`（内部 `const_cast`，C 函数不修改该缓冲区） |
| string 重载 | 见 3.1 |
| 封装范围 | 只封装任务列出的接口 |
| 命名与位置 | `include/gplat_connection.h`，全局命名空间，方法名沿用 C 名；`write_plc_*` 保留 `=delete` 模板 |
| 测试与文档 | 新增 `testapp6`（加入 Makefile），更新 `Doc/api_reference.md` 和 `CLAUDE.md` |

## 3. 实现（`include/gplat_connection.h`）

### 3.1 接口

- 生命周期：`GplatConnection(std::string server, int port)`、`open()`、`close()`、`is_open()`；不可拷贝，可移动（被移动对象变为未连接，移动赋值会先关闭自己原有的连接）。
- 队列：`readq`、`writeq`、`clearq`、`peekq(qname, position, record, actsize, recordhead = nullptr)`。
- Board：`readb(tag, value, actsize, timestamp = nullptr)`、`writeb`、`writeb_notpost`。
- 字符串重载：

| 方法 | 调用的 C 函数 |
|---|---|
| `readb_string(tag, char*, int, timespec* = nullptr)` | `readb_string` |
| `readb_string(tag, std::string&, timespec* = nullptr)` | `readb_string2` |
| `writeb_string(tag, const char*)` | `writeb_string` |
| `writeb_string(tag, const std::string&)` | `writeb_string2` |
| `writeb_string_notpost(tag, const char*)` | `writeb_string_notpost` |
| `writeb_string_notpost(tag, const std::string&)` | `writeb_string_notpost`（传 `c_str()`） |

- 订阅：`subscribe`、`subscribedelaypost`、`waitpostdata(tagname, value, buffersize, timeout)`。
- 请求 / 响应：`getresponse(request_tag, request_value, request_size, response_tag, response_value, response_size, timeout_ms = 2000)`。
- PLC：`write_plc_{string,bool,short,ushort,int,uint,float}`，每个非模板版本旁边保留 `template<typename T> ... = delete`，禁止隐式类型转换。
- 类内的方法名遮蔽了同名全局 C 函数，实现中统一用 `::readq(...)` 形式调用。

### 3.2 连接被 C 库关闭的判定

核对 `higplat.cpp` 中所有 `close(sockfd)` 分支后得到的规则。判定为已关闭时只把 `m_sockfd` 置为 -1，不再 close，避免重复关闭别的线程新打开的同号 fd：

| 规则 | 适用方法 | 视为已关闭的条件 |
|---|---|---|
| `Default` | 除下行外的所有方法 | 调用失败且 error 为 0（`send` 返回 0 时 errno 可能为 0）、< 1000（errno）、`ERROR_SOCKET_NOT_CONNECTED`、`ERROR_INVALID_RESPONSE`、`ERROR_BUFFER_TOO_SMALL`（后三者对已封装接口只由客户端检测并 close，服务端不会返回） |
| `AnyServerError` | `subscribe`、`waitpostdata` | 任何非 0 错误（这两个 C 函数对服务端错误也会 close） |

- 两条规则都排除 `ERROR_INVALID_PARAMETER`（参数校验失败时 C 库不 close）和 `ERROR_WAIT_TIMEOUT`。
- 统一入口 `call(rule, f)`：未连接返回 `ERROR_SOCKET_NOT_CONNECTED`；成功时返回 error（只有 `waitpostdata` 超时非 0）；失败且 error 为 0 时返回 `ERROR_SOCKET_NOT_CONNECTED`。
- C 库对 Fatal 级错误（`ERROR_BUFFER_TOO_SMALL`、`ERROR_TAG_NOT_EXIST`、`ERROR_RECORDSIZE`）在 `AutoErrorCheck` 析构时抛异常：`call()` 用 `catch (...)` 先按 error 更新连接状态再 `throw;`。

已知限制：
- 若服务端返回 < 1000 的错误码会被误判为断线，后果是泄漏一个 fd，不会重复 close。
- `is_open()` 只反映本地状态，对端关闭要到下一次调用失败才能感知。

## 4. testapp6

`testapp6 [ip] [port]`（默认 `127.0.0.1:8777`），先用 C 接口 `createtag` / `createqueue` 准备 `TEST6_INT`、`TEST6_STR`、`TEST6_REQ` / `TEST6_RSP`、`TEST6_NOREQ` / `TEST6_NORSP` 和队列 `TEST6_QUEUE`（已存在时忽略）。

| 场景 | 验证内容 |
|---|---|
| 编译期 | `write_plc_int(double/long)` 被删除、`int` 可用；类不可拷贝、可 `noexcept` 移动 |
| 生命周期 | 构造不连接；未连接返回 `ERROR_SOCKET_NOT_CONNECTED`；重复 `open()`；移动构造 / 移动赋值；`close()` 两次；重新打开；连接关闭端口失败 |
| Board | `writeb` / `readb`（含 timestamp）、`writeb_notpost`；四个字符串重载及 notpost 版本；读不存在的 tag 抛异常且连接保持可用 |
| Queue | `clearq`、`writeq` ×3、`peekq`（`PEEK_NEXT` / `PEEK_LATEST`）、`readq` 顺序、空队列出错但连接保持 |
| 订阅 | `subscribe` + `waitpostdata`；`writeb_notpost` 后超时返回 `ERROR_WAIT_TIMEOUT` 且连接保持；`subscribedelaypost`；缓冲区不足时 C 库 close 并抛异常，封装类识别为断开，后续调用返回 `ERROR_SOCKET_NOT_CONNECTED`，重新 `open()` 后可用 |
| 请求 / 响应 | 响应线程（独立 `GplatConnection`）应答 10 次 `getresponse`；无人应答时返回 `ERROR_RESPONSE_TIMEOUT` 且连接保持 |

`write_plc_*` 未做运行测试。

测试结果：在 `/tmp` 下独立的 gplat 实例（端口 8796）上连续运行两次均 `ALL PASSED`。
