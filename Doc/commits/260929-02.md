# 260929-02 toolgplat monitor 命令：动态监控 tag 值变化

## 1. 需求要点

1. 原来 `select <tag>` 只能查看 tag 的当前值，需要新增命令动态监控 tag 值的变化，如 `monitor tagint00_00`。
2. 实现方式：先 `subscribe` 订阅，再循环调用 `waitpostdata` 等待事件。
3. 监控期间输入 `q` 退出监控。

实施前确认的决策：

| 问题 | 结论 |
|---|---|
| 退出方式 | 直接按 `q` 立即退出，无需回车（终端临时切换为非规范模式） |
| 输出格式 | 时间戳行 + 与 `select` 相同的值显示（结构体多行展开） |
| 多 tag | 支持 `monitor tagA tagB ...`，每次输出前标注 tag 名 |
| 初始值 | 进入监控时先显示一次当前值 |

## 2. 设计要点

| 问题 | 结论 |
|---|---|
| 没有取消订阅的接口，在会话主连接上订阅后，服务端会一直向该连接的 `m_listPost` 积压事件 | 监控使用到同一 host 的**独立连接**；退出时关闭该连接，服务端在断开时调用 `CancelSubscribe` 清理订阅 |
| `waitpostdata` 带超时轮询时，服务端每次超时都会在其 stdout 打印 "超时时间到" | 接收线程用 `waitpostdata(..., -1)` 无限等待；主线程用 `poll` 监视键盘（间隔 200ms，同时检查接收线程是否已结束） |
| 如何唤醒阻塞在 `waitpostdata` 中的接收线程 | 主线程对监控连接调用 `shutdown(SHUT_RDWR)`，`waitpostdata` 读到 EOF 后由 higplat 关闭连接并返回 `false`，线程退出后 `join`。higplat 出错时已经关闭了 fd，所以之后不再调用 `disconnectgplat` |
| 显示的值来自推送包体还是重新读取 | 使用推送包体：连续快速写入时每次都能看到各自的值。`WriteB` 要求写入大小等于 tag 大小，包体即完整 tag；字符串 tag 的包体为字符串，`waitpostdata` 会在末尾补 `'\0'` |
| 时间戳 | POST 消息不带写入时间，显示本地接收时间（精确到毫秒）；初始值仍显示服务端的 `last write time` |
| Ctrl+C | 非规范模式下同时关闭 `ISIG`，Ctrl+C 与 `q` 一样退出监控，避免进程被终止后终端停留在非规范模式 |
| 重复 tag | 去重后再订阅，避免同一次写入收到两次事件 |
| `nopost` 写入 | 不会触发发布，监控看不到，这一点写入帮助 |

## 3. 使用示例

```
127.0.0.1:BOARD>monitor tagint00_00
===== tagint00_00  current =====
value: 666
-------------------------------------
last write time: Tue Sep 29 13:59:43 2026
Monitoring 1 tag(s). Press 'q' to stop.
===== tagint00_00  2026-09-29 14:48:13.299 =====
value: 777
===== tagint00_00  2026-09-29 14:48:13.299 =====
value: 999
Monitor stopped.
```

帮助：

```
Usage: monitor <tagName> [tagName ...]
Description: Shows the current value of the tags, then displays every new value
             published by the server (writes with 'nopost' are not shown).
             Press 'q' to stop monitoring.
```

## 4. 代码改动

### 4.1 `toolgplat/monitor.cpp/.h`（新增）

- `MonitorTags(conn, host, port, tagNames)`：
  1. 在主连接上用 `ReadTagType` 读取每个 tag 的类型（去重），任一失败则放弃；
  2. 用 `PrintTag` 显示当前值；
  3. `connectgplat` 建立监控连接，逐个 `subscribe`（失败时 higplat 已关闭连接）；
  4. 启动接收线程 `ReceivePosts`，主线程在 `RawTerminal` 作用域内 `WaitForQuit`；
  5. 退出时 `shutdown` 监控连接并 `join` 接收线程。
- `ReceivePosts`：循环 `waitpostdata`，按 tag 名查类型后输出时间戳行和 `PrintTagData`；连接意外断开时提示 `Monitor connection lost`；捕获 higplat 致命错误码抛出的异常。
- `RawTerminal`：RAII，关闭 `ICANON | ECHO | ISIG`，析构时恢复；stdin 不是终端时不做处理。
- 接收缓冲区大小为 `MAXMSGLEN + 1`（16385）。

### 4.2 `toolgplat/display.cpp/.h`

- 值的打印与读取拆分：新增 `PrintSimpleValue`、`PrintStringValue`、`PrintStructValue`、`FindPrintableType`、`FindLocalStruct`、`PrintRaw`，`PrintSimpleTag` / `PrintStringTag` / `PrintStructTag` / `PrintQueueRecord` 改为调用它们。
- 新增导出函数 `PrintTagData(header, className, data, size)`：按类型描述符从缓冲区打印 tag 值。
- `ReadTagType` 从 `main.cpp` 移入并导出，`PrintTag` 也改用它。
- `display.h` 包含 `type_handle.h`（`TypeDescriptorHeader`）。

### 4.3 `toolgplat/main.cpp`

- 新增 Board 作用域命令 `monitor`（`CmdMonitor`）及帮助；`open` 帮助中 Board 命令列表加入 `monitor`。
- 删除本地的 `ReadTagType`（改用 display 中的版本）。

### 4.4 构建

- `Makefile`：`TOOLGPLAT_LDFLAGS` 加入 `-lpthread`。
- `toolgplat.vcxproj`：加入 `monitor.cpp/.h`，`LibraryDependencies` 加入 `pthread`。

## 5. 验证

- `make toolgplat` 编译通过，无警告。
- 连接 8777 上运行中的服务端：
  - `monitor tagint00_00 tagint00_00 vehicle1`：`vehicle1` 是队列不是 tag，读取类型失败（错误码 1018），不进入监控。
  - `monitor tagint00_00 tagint00_00`：显示当前值 666；另一个 toolgplat 依次执行 `write tagint00_00 777`、`write tagint00_00 nopost 888`、`write tagint00_00 999`，监控端只收到 777 和 999，且每次写入只显示一次（重复 tag 已去重）。
  - 按 `q` 后显示 `Monitor stopped.` 并回到提示符；随后 `select tagint00_00` 在主连接上正常返回 999。
- 结构体 / 字符串 / 数组 tag 的推送显示、Ctrl+C 退出、服务端断开时的提示未手工验证。

## 6. 遗留事项

- 连接因服务端断开而结束的同时用户按下 `q` 时，主线程可能对已关闭的 fd 调用 `shutdown`；这期间没有打开新 fd，影响可以忽略。
- 监控期间服务端重启不会自动重连，需重新执行 `monitor`。
