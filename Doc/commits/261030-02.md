# 20261030-02 重构 gplat/ngx_c_slogic.cxx：消除重复、语法现代化，修复几处越界和崩溃缺陷

`gplat/ngx_c_slogic.cxx`（1616 行）是服务端的消息分发和业务处理层。约 20 个 Handler 各自重复"分配发送缓冲区 → 加连接锁 → 拷贝消息头/包头 → `msgSend`"；"连接正在 `waitpostdata` 就立即发送，否则进入待发队列"的投递逻辑在 4 处各写了一遍。本次重构抽出公共辅助函数、改用 C++17 写法，并修复了几处由客户端数据触发的越界和崩溃。重构后约 1220 行。

原则是不过度重构：仍是一个 `CLogicSocket` 类，request/response 部分没有拆成独立的类；函数顺序与原文件基本一致，便于对照。

## 一、不变的部分

- **线协议**：`MSGHEAD` 布局、`MSGID`、各消息的字段含义与应答格式不变。合法客户端（`libhigplat`）看到的行为不变。
- **锁规则**：连接锁 `logicPorcMutex` → `sendMutex` → `m_sendMessageQueueMutex` 的顺序不变；持有 `m_reqMutex` 时仍不获取连接锁。`HandleSubscribe`、`HandleRegisterPlcServer`、`HandlePostWait` 仍在同一把连接锁内完成状态修改和应答。
- **Pub/Sub 与 getresponse**：事件投递、`POST_DELAY` 延时事件、待发队列上限、请求排队和超时的逻辑不变。
- **对外接口**：`CLogicSocket` 的公有成员函数名不变（只是参数改为 `const` 引用/`const char*`，现有调用方无需修改）。

## 二、重构内容

### 1. 抽出公共辅助函数

文件内匿名命名空间（不进头文件）：

| 函数 | 作用 |
|---|---|
| `AllocSendBuf(bodyLen)` | 分配"消息头 + 包头 + 包体"发送缓冲区 |
| `PkgHeadOf` / `BodyOf` / `PayloadOf` | 定位发送缓冲区中的包头、包体，以及请求包中紧跟包头的数据 |
| `CopyName` | 定长名字字段的有界拷贝，保证零终止，替换原来的 `strcpy` |
| `ResultCode(ok)` | `ok ? 0 : GetLastErrorQ()` |
| `IsValidBodySize` / `PayloadFits` | 客户端给出的长度校验（见第三节） |
| `BuildPacket` / `BuildPostPacket` | 构造主动发往某连接的包（POST、POSTWAIT 超时、GETRESPONSE 应答） |
| `IsTimerTag` | 判断是否为 `timer_500ms` 等虚拟定时器 tag |

`CLogicSocket` 新增私有成员：

| 函数 | 作用 |
|---|---|
| `SendReply` / `SendReplyLocked` | 用请求的消息头和改写后的包头组装应答并发送；前者内部加连接锁，后者要求调用者已持有 |
| `SendHeadReply` | 无包体应答（`bodysize` 置 0） |
| `DeliverPostLocked` | 停止等待超时定时器，连接正在等待则立即发送，否则 `EnqueuePost`；调用者须持有连接锁 |

`NotifySubscriber`（`DEFAULT` 和 `POST_DELAY` 两个分支）、`NotifyTimerSubscriber`、`NotifyPlcIoSever` 统一改用 `BuildPostPacket` + `DeliverPostLocked`。`POST_DELAY` 的定时器回调改为捕获 `this`，不再通过全局 `g_socket` 调用 `msgSend`。

### 2. 合并与删除

- `HandleWriteBStringPlc` 与 `HandleWriteBPlc` 原本逐行相同，现在前者直接调用后者。
- 删除注释掉的旧代码、未使用的变量（`pPkgBody`、`data`），以及只是为了"发布订阅时能拿到正确长度"、实际没有用到的 `pPkgHead->bodysize = pPkgHead->datasize`。
- `HandleWriteQ` 不再先把 `qname` 拷到 `itemname` 再发布，直接以 `qname` 作为事件名，效果相同。

### 3. 语法现代化

- `typedef` 成员函数指针 → `using Handler`；`NULL`/`0` → `nullptr`；C 风格强制转换 → `reinterpret_cast`/`static_cast`。
- `statusHandler[]` 改为 `static constexpr`，并加 `static_assert(std::size(statusHandler) == LISTTAGS + 1)`，新增 `MSGID` 时如果忘记登记会编译失败；替换原来的 `AUTH_TOTAL_COMMANDS` 宏。
- 头文件：构造/析构函数 `= default`；覆盖基类的虚函数（`Initialize`、`threadRecvProcFunc`、`CancelSubscribe`、`CancelRequest`）加 `override`；`#define REQUEST_QUEUE_MAX` → `inline constexpr std::size_t`；`PendingRequest` 的 `pConn`/`iCurrsequence`/`responseSize` 加默认初始值。
- `NotifySubscriber`/`NotifyTimerSubscriber`/`NotifyPlcIoSever` 的 `std::string` 参数改为 `const std::string&`，包体参数改为 `const char*`；`DeliverResponse` 的数据参数改为 `const char*`。
- range-for 改为 `const auto&`（原来逐个拷贝 `EventNode`/`std::string`），`CancelRequest` 使用结构化绑定。
- `HandlePostWait` 定义上残留的默认参数去掉；消除变量遮蔽（局部变量 `strlen` 遮蔽同名函数、内层 `pPkgHead` 遮蔽外层）。
- `HandleSubscribe` 的定时器 tag 判断改为 `std::string_view` 数组 + `std::find`。
- `g_buffer` 移入匿名命名空间（内部链接）；去掉未使用的 C 头文件，改用 `<cstring>` 等。

`-Wall -Wextra -Wshadow` 下本文件不再有警告（原文件 2 条）。

## 三、顺带修复的缺陷

这些缺陷只能由畸形请求触发（`libhigplat` 客户端不会发出这样的包），但会导致服务端崩溃或越界访问。

1. **读请求长度未校验，可致 worker 崩溃**：READB、READQ、READTYPE 按客户端给的 `datasize` 直接 `AllocMemory`（即 `new char[n]`）。`datasize` 为负数或接近 `INT_MAX` 时总长度溢出为负，`new` 抛出 `std::bad_array_new_length`，线程池线程里无人捕获，进程终止。现在 `datasize` 不在 `[0, MAXMSGLEN]` 内时直接以 `ERROR_RECORDSIZE` 应答。READBOARDINFO 原来先按 `datasize` 分配、再判断是否等于 `sizeof(BOARD_INFO)`，现在先判断，只分配 `sizeof(BOARD_INFO)`。
2. **写请求越界读包体**：WRITEB、WRITEQ、WRITEBSTRING、WRITEBPLC、WRITEBSTRINGPLC 按 `datasize` 读取包体，而不检查实际收到的包体长度。`datasize` 大于包体时会读出接收缓冲区之外的数据并写进 tag（用原服务端验证：声明 4 字节、只带 2 字节，tag 被写成 `0x6655`，高位来自越界内存）。现在 `datasize` 为负或大于实际包体长度时以 `ERROR_RECORDSIZE` 拒绝，不写入、不发布。
3. **READBSTRING 可溢出线程局部缓冲区**：`ReadB_String2` 只检查字符串长度不超过调用者给的 `actSize`，而 `actSize` 来自客户端，`g_buffer` 只有 `MAXMSGLEN` 字节。若 tag 中字符串超过 `MAXMSGLEN`（本地 API 可写入）且客户端声明更大的缓冲区，就会溢出。现在缓冲区大小按 `std::min(datasize, MAXMSGLEN)` 截断，超长字符串返回 `BUFFER_TOO_SMALL`。
4. **名字字段零终止**：`threadRecvProcFunc` 在分发前统一给 `qname`/`itemname` 补零终止（原来只有 `HandleSubscribe`、`HandleGetResponse`、`HandleListTags` 各自补）。`libhigplat` 的 `copy_name` 本来就保证零终止，对合法客户端无影响。

## 四、细微的行为变化

- `HandleClearQ`、`HandleClearB` 应答时也加连接锁，与其他 Handler 一致（原来这两个不加）。只是多一次无竞争的加锁。
- 消息码按 `int` 校验。原来先截断为 `unsigned short`，例如 `65536 + 19` 会被当成 READB 分发；现在超出范围一律丢弃并记日志。
- 上面第三节的畸形请求现在得到 `ERROR_RECORDSIZE` 应答，而不是崩溃或越界。

## 五、验证

- `make gplat`：`-Wall` 无警告。
- 常规回归 `bin/testsuite`：重构前后结果相同，66 passed / 0 failed / 3 skipped。
- `make test-all`（ASan 构建，放行破坏性和压力用例）：89 passed / 0 failed / 0 xfail / 0 xpass / 0 skipped。
- 新增两个用例（`testsuite/cases/test_protocol.cpp`，标签 `protocol destructive`）：
  - `protocol.read_size_out_of_range`：READB/READTYPE/READQ 的 `datasize` 取 `-1`、`INT32_MIN`、`MAXMSGLEN+1`、`INT32_MAX`，期望 `ERROR_RECORDSIZE`、连接可继续使用、服务端存活；READBSTRING 以 `INT32_MAX` 作缓冲区大小仍能正常读取。
  - `protocol.write_datasize_exceeds_body`：五种写请求声明 4 字节、只带 2 字节包体，期望 `ERROR_RECORDSIZE` 且 tag 内容不变。
  - 用原 `ngx_c_slogic.cxx` 编出的服务端（`--gplat` 指定）运行，这两个用例均失败（第一个 11 处未拒绝且连接失效，第二个 tag 被改写），确认用例能覆盖到缺陷。
