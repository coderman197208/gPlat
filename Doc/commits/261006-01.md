# 20261006-01 修复 worker 退出时偶发卡死（SIGCHLD 处理函数在 worker 中误回收子进程）

`make test-all` 中 `stress.queue_producer_consumer` 偶发 `server_fixture.cpp:123  server graceful shutdown timed out`，同一 seed 多次运行无法复现。

## 一、结论

- 业务无影响：该用例 4002 个检查全部通过，读写记录数一致；失败发生在用例结束后 `ServerFixture::stop()` 里：master 收到 SIGTERM 后 8 秒内 worker 没有退出，被强杀。
- 是服务端退出阶段的真实缺陷（时序竞争），不是测试偶发问题；只影响进程退出，不影响数据和运行期稳定性。仅在 ASan/LSan 构建下确认过。
- 不可复现的原因：seed 只决定负载数据，触发条件是退出时的线程/进程时序。

## 二、复现与定位

- 在同一个 ASan 构建、同一用例上循环运行，约每 60～130 次出现一次（一次在第 9 次，一次在第 132 次）。
- 挂起时的现场：master 停在 `sigsuspend`；worker 只剩 1 个线程，在 futex 上永久等待；worker 日志停在"子进程退出了"，缺少正常情况下紧随其后的 `waitpid() failed! (10: No child processes)`。
- 根因（推断；环境没有 gdb 且 `/proc/<pid>/stack` 需要 root，没有拿到调用栈）：
  - `ngx_signal.cxx` 的信号处理函数 `ngx_signal_handler` 由 master 注册，被 worker 继承。
  - worker `exit()` 时，LSan 会 fork 一个检查子进程；该子进程退出后给 worker 发 SIGCHLD。
  - worker 里的处理函数执行了 `ngx_process_get_status()`（`waitpid(-1)`），可能抢先回收这个子进程，使 LSan 自己等待它时永久阻塞。
- 旁证：正常运行的日志里 worker 一定有 `waitpid() failed! (No child processes)`（回收了 LSan 子进程之后再无子进程），卡死那次没有。

## 三、修改

`gplat/ngx_signal.cxx`：`SIGCHLD` 分支加 `ngx_process == NGX_PROCESS_MASTER` 条件，只有 master 回收子进程并置 `g_stopEventMain`，worker 不再 `waitpid`。master 的行为不变；worker 从未需要这段逻辑（它没有自己 fork 的子进程，`g_stopEventMain` 只在 master 循环中使用）。

## 四、验证

- 重新 `make ASAN=1 asan-build` 后单跑该用例通过；worker 日志不再出现 `waitpid() failed!`，master 能正常收到 worker 退出的 SIGCHLD 并退出。
- 因为原概率只有 1/60～1/130，几次通过不能证明已消除。建议在 CI 里把 `stress.queue_producer_consumer` 多跑几百次观察。

## 六、复现脚本

循环运行用例，在用例开始约 3.5 秒后（正常情况下用例约 1.4 秒就结束）如果测试进程仍在，就认为卡住，并打印 gplat 各进程/线程的状态：

```bash
#!/bin/bash
cd /home/gyb/projects/gPlat
for i in $(seq 1 300); do
  build/asan/bin/testsuite --expect-asan --all -f stress.queue_producer_consumer > /tmp/run.out 2>&1 &
  tp=$!
  sleep 3.5
  if [ -d /proc/$tp ]; then
    echo "iter $i hang"
    for p in $(pgrep -x gplat); do
      echo "== $p"; grep -E "State|Threads|PPid" /proc/$p/status
      for t in /proc/$p/task/*; do echo "$(basename $t) $(cat $t/comm) st=$(awk '{print $3}' $t/stat) wchan=$(cat $t/wchan 2>/dev/null) $(cat $t/syscall 2>/dev/null | cut -c1-70)"; done
      ls -l /proc/$p/fd | wc -l
    done
    ps -eo pid,ppid,stat,wchan:20,cmd | grep -E "gplat|testsuite" | grep -v grep
    wait $tp
    echo done; exit 0
  fi
  wait $tp
done
echo nohang
```

注意：脚本里用 `pgrep -x gplat` 会同时匹配同机其它 gplat 进程；本次运行时机器上另有一组常驻的 gplat master/worker，输出里要按 PPid 区分。
