# 20261030-01 重构 higplat：按职责拆分 higplat.cpp，语法现代化

`higplat/higplat.cpp`（4169 行）把错误上报、网络客户端 API、本地 Queue API 和本地 Board API 混在一个文件里。网络 API 约 30 个函数重复同一套"拼包头 → 发送 → 收响应 → 校验"代码，本地 API 到处手写 `pthread_mutex_lock`/`unlock`。本次重构按职责拆分文件、消除重复、改用现代 C++17 写法，并顺带修复了几处越界和崩溃缺陷。

## 一、不变的部分

- **对外接口**：`include/higplat.h` 声明的 `extern "C"` 函数签名不变；`libhigplat.so` 导出的 `extern "C"` 符号集合与重构前完全一致（新旧 `nm -D` 对比），没有新增。
- **磁盘格式**：`BOARD_HEAD`、`BOARD_INDEX_STRUCT`、`QUEUE_HEAD`、`RECORD_HEAD` 的布局，以及 `hash1`/`hash2`（板索引槽位会持久化）逐位不变；已删除项在内存表和板索引里仍写入墓碑名 `CT0D9GG_~$59`。
- **网络协议**：发送和接收的字节不变，包头、包体仍分两次 `send`。
- **锁语义**：Board 的加锁顺序（索引锁 → 条带锁 0..63）和各操作的加锁范围不变。
- **构建**：Makefile 用通配符收集 `higplat/*.cpp`，不需要修改。

## 二、新的文件结构

| 文件 | 职责 |
|---|---|
| `higplat/net_client.cpp` | 网络客户端 API：连接、socket I/O（`send_request`/`recv_response`/`fail_connection`/`discard_body`）、所有带 `sockfd` 的接口 |
| `higplat/local_queue.cpp` | 本地队列 API：`CreateQ`、`CreateAndLoadQ`、`ReadQ`、`WriteQ`、`PeekQRecord`、`ListQ` 等 |
| `higplat/local_board.cpp` | 本地 Board API：`CreateB`、`CreateItem`、`DeleteItem`、`ReadB`、`WriteB`、`ListTags` 等 |
| `higplat/qbd_table.cpp` | 已载入文件表（开放寻址哈希表）、QBD 目录（`SetQbdPath`/`GPLAT_QBD_PATH`）、`LoadQ`/`UnloadQ`/`UnloadAll`/`FlushQFile`、`ReadType`、通用的文件创建 `CreateQbdFile` |
| `higplat/error.cpp` | 错误钩子、`ReportError`、`SetErrorHook`、`GetErrorCategory`、`IsFatalError`、`GetLastErrorQ` |
| `higplat/error.h`（新） | 从 `qbd.h` 移出的 `ErrorCategory`/`GetErrorInfo`，以及 `AutoErrorCheck`、`g_lastError` 声明 |
| `higplat/qbd.h`（重写） | 只保留文件布局、常量、已载入表接口和共享的内联辅助函数 |

两个内部头文件在 `#pragma GCC visibility push(hidden)` 区段内声明库内部符号，因此它们不再从 `libhigplat.so` 导出，库内部调用也不再经过 PLT。`include/higplat.h` 在区段之前被包含，公共函数保持默认可见性。

## 三、重构内容

### 1. 网络 API

- 新增辅助函数：`copy_name`（截断并保证 `'\0'` 结尾）、`make_head`/`make_board_head`、`transact`（自动设置 `bodysize`，发送包头和包体，再收响应包头）、`recv_status`（无包体响应）、`recv_ack`（要求回显请求 id）、`recv_body`（包体读入调用方缓冲区，放不下时读掉丢弃）。
- `writeb_`/`writeb_plc` 合并为 `write_board(id, …, start)`；`writeb_string_`/`writeb_string_plc` 合并为 `write_board_string`。
- 每次调用不再构造并清零 16KB 的 `MSGSTRUCT`（原来只发送其中的包头），改为只构造 `MSGHEAD`。
- `connectgplat` 去掉多余的 `setblocking`：`unblock_connect` 已恢复 socket 原来的阻塞标志。
- 每个函数的参数校验顺序和错误码保持原样；`AutoErrorCheck` 仍只放在导出函数里。

### 2. 本地 API

- 队列锁从 `new pthread_mutex_t` 改为 `new std::mutex`，所有手写 lock/unlock 改为 `std::lock_guard`。
- Board 原来手写的"索引锁下查找 → 取条带锁 → 释放索引锁"改为 RAII 类 `ItemAccess`，加锁顺序不变。
- 提取共享辅助函数：
  - `FetchQueue`/`FetchBoard`：取已载入文件并校验类型；
  - `BoardProbe`/`FindBoardItem`/`StripeMutex`/`BoardData`/`BoardTypeArea`：板索引的探测与寻址；
  - `QueueRecord`：记录寻址；
  - `MulReadCount`/`MulReadCopy`：`MulReadQ` 与 `MulReadQ2` 共用；
  - `ReadStringItem`：`ReadB_String` 与 `ReadB_String2` 共用；
  - `CreateQbdFile`：`CreateQ` 与 `CreateB` 共用的"删旧文件 → 建目录 → 创建 → mmap → 初始化 → msync"流程。
- `inserttab`/`fetchtab`/`deletetab` 改为整结构赋值。`TABLE_MSG` 去掉 Linux 下无用的 `hMapFile` 字段，各成员加了默认初始化。

### 3. 语法现代化

- `#define` 常量改为 `constexpr`。`QUEUEHEADSIZE`/`RECORDHEADSIZE` 仍为 `size_t`，偏移运算的类型不变。
- 路径拼接从固定 100 字节的 `strcpy`/`strcat` 改为 `std::string`。
- 时间格式化 `gettime` 改为 `FormatLocalTime`，使用线程安全的 `localtime_r`；`strerror` 改为线程安全的 `ErrnoMessage`。
- 匿名命名空间、`static_cast`、范围 for、`enum class EventId`；删除 Windows 遗留的注释代码和注释掉的 `readn_timeout`。
- 删除无用的全局量 `g_buffer`（与服务端 `ngx_c_slogic.cxx` 的同名变量冲突）、`usereason`，以及未使用的 `fetchtab1`。
- `qbd.h` 增加 `static_assert`，固定 `QUEUE_HEAD`（56）、`RECORD_HEAD`（48）的大小。64 位下还固定 `BOARD_INDEX_STRUCT`（80）的大小和 `BOARD_HEAD::mutex_rw` 的偏移（40）。

## 四、顺带修复的缺陷

以下在原代码中都是越界、崩溃或静默失败，合法调用的行为不受影响：

| 位置 | 原问题 | 现在 |
|---|---|---|
| `ReadType` | 忽略 `buffSize`；服务端按客户端传来的 `datasize` 分配缓冲区，客户端可远程触发服务端堆溢出；Board 分支查找时不加索引锁 | 放不下返回 `ERROR_BUFFER_TOO_SMALL`；Board 分支持索引锁 |
| 本地 Queue/Board 函数 | 只有 `ReadHead`/`PeekQRecord`/`ListTags`/`ClearB` 校验文件类型：远程 `writeq("BOARD")` 会把板文件当队列写坏，对队列名调用 Board 接口会解引用空的 `pmutex_rw` | `FetchQueue`/`FetchBoard` 统一校验，返回 `ERROR_OPERATE_PROHIBIT` |
| `inserttab` → `FlushQFile` | 插表时不拷贝 `filesize`，`FlushQFile` 实际以长度 0 调用 `msync`，什么也没刷 | 整结构拷贝，按真实文件长度刷盘（仓库内无调用方） |
| `CreateItem` | 复用已删除项的槽位时沿用旧的 `strlenth`；名字 ≥ 40 字节时 `strcpy` 溢出索引项 | `strlenth` 置 0；名字过长返回 `ERROR_PARAMETER_SIZE` |
| `CreateQ`/`CreateB`/`LoadQ` | 允许 40 字符的名字，`LoadQ` 的 `strcpy` 溢出 `dqname[40]` | 名字长度 ≥ 40 返回 `ERROR_FILENAME_TOO_LONG` |
| `ReadB_String`/`ReadB_String2` | 只在索引锁下检查 `strlenth`，之后在条带锁下按 `strlenth` 拷贝；并发写入可能使拷贝超出缓冲区 | 在条带锁下检查并拷贝 |
| `WriteB` 子项写 | 未检查负偏移 | 负偏移、负长度返回 `ERROR_RECORDSIZE` |
| `WriteB_String`/`WriteQ` | 负长度导致超大 `memcpy` | 分别返回 `ERROR_PARAMETER_SIZE` / `ERROR_RECORDSIZE` |
| `WriteQ`/`ReadQ` 的 IP | 无界 `strcpy` 写 16 字节的 `remoteIp` | 截断拷贝 |
| `ReadInfoB` | 名字 `strcpy` 进 `char[24]` 会溢出；实际项数多于 `indexcount` 时越界写调用方缓冲区 | 截断到 23 字符，不越界；返回值语义不变 |
| `MulReadQ2` | 起始位置越界且 `pRecordSize == NULL` 时解引用空指针 | 先判空 |
| `LoadQ` | 文件既非 Board 也非 Queue 时 `pmutex_rw` 未初始化；插表失败时不 `munmap` | 默认初始化为空；失败时 `munmap` |
| `UnloadQ`/`UnloadAll` | 不加表锁就修改已载入表 | 持表锁；`FlushQFile` 在锁外 `msync`，避免长时间持锁 |
| `createqueue`/`readtype`（网络） | `queuename`/`ptypesize` 为空时崩溃 | 返回 `ERROR_INVALID_PARAMETER` |
| `recv_body`（网络） | 负的 `bodysize` 被当作 0 处理；`readb_string` 会写 `value[负数]` | 视为无效响应：`ERROR_INVALID_RESPONSE`，并 shutdown 连接 |
| `clearq`（网络） | 不检查响应是否带包体 | 与其它无包体响应一样校验；对正常服务端无差别 |

## 五、验证

- **编译**：`-Wall -Wextra -Wshadow` 零警告。
- **导出符号**：新旧 `nm -D` 对比，只移除了内部符号（`table`、`errorCode`、`g_buffer`、`dataQuePath`、`fetchtab`、`send_all`、`writeb_` 等）；`bin/` 下所有可执行文件导入的符号都还在。
- **回归**：`make test` 66 通过 / 3 跳过，与重构前的基线相同；`make test-all`（ASan，含破坏性、压力用例）87/87 通过。
- **新旧库对比**：用 git 中的旧源码另编一份旧库，两份库跑同一个本地 API 探针：
  - **读路径**：对仓库 `qbdfile/` 的副本（1125 个 tag、5 个队列），`ReadB`/`ReadType`/`GetStringLength`/`ReadHead`/`PeekQRecord`/`IsEmptyQ`/`IsFullQ` 的输出逐行一致。
  - **写路径**：79 步确定性操作（建板、建项、整写/子项写、字符串读写、删除压缩、普通/移位队列的读写/Peek/MulRead/SetPtr/Clear、卸载重载），返回值和错误码完全一致；生成的 BOARD 和队列文件在屏蔽时间戳字段后逐字节相同（板文件分别比较了 `ClearB` 前后）。
- **修复项**：逐项单独验证（只在新库上，旧库上这些场景是未定义行为）。`FlushQFile` 用 `LD_PRELOAD` 拦截 `msync`，确认按真实文件长度调用。
- **代码审查**：独立审查代理逐函数对照旧代码，未发现非预期的语义差异。

32 位构建未实测（本机缺少 multilib）；依赖 64 位对齐的断言已放在 `__LP64__` 条件内。

## 七、未处理

以下是原有问题，与本次重构无关，保持原状：

- 板索引的 `hash1` 对 `TABLESIZE`（277）取模，而索引有 `INDEXSIZE`（7177）个槽，所有 tag 的起始探测位置都落在前 277 个槽内，形成聚集。哈希值决定了已持久化的槽位，修改会破坏现有板文件。
- `UnloadQ`/`UnloadAll` 不 `munmap`（其它线程可能仍持有该映射）；`UnloadAll` 不重置引用计数，也不析构条带锁。
- `ReadType` 找不到 tag 时不设置 `GetLastErrorQ`，服务端会回传上一次的错误码。保留原状，以免改变 `readtype` 调用方看到的错误码。
