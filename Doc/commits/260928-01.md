# 260928-01 toolgplat 代码重构与优化

需求来源：[Doc/tasks/20260928.md](../tasks/20260928.md)

## 1. 需求要点

- 目标项目：toolgplat。
- 从可维护、可扩展的角度审阅并优化代码，参考 KISS、YAGNI、DRY、高内聚松耦合等原则。
- 代码可读性好、命名清晰、能够自我解释。

## 2. 重构前的主要问题

| 类别 | 问题 |
|---|---|
| 结构 | 全部逻辑（REPL、命令分发、tag/队列创建、批量导入、值显示、帮助）堆在一个约 1050 行的 `main.cpp` 中 |
| YAGNI | `QBDType` 枚举中 `queue` 从未使用；`GlobalObj` 静态成员 + 过时的 .NET 注释；`g_qbdtype`、`qbdname`、`prefix` 多个全局变量表达同一状态 |
| DRY | `CreateTag` 三个分支（`类型名$大小` / 已注册 struct / 内置类型）几乎相同；`HandleCreateQueue` 再复制一遍类型描述符构造；嵌套 struct 打印与字段打印重复；分词、去空白、转小写逻辑多处复制；`GetTypeByName` / `GetTypeByCode` 两张内容相同的表 |
| 分发 | `Analyse` 为长 `if` 链；`HandleHelp` 与命令列表分离，`delete` 分支重复，缺少 `types`、`open`、`exit` 的帮助 |
| 命名 | 魔法数字 `16000`、`8777`、`-1`、`2048`；局部变量 `typecode` 遮蔽同名外层变量 |

## 3. 重构后的文件结构

| 文件 | 职责 |
|---|---|
| `toolgplat/main.cpp` | REPL 循环、`Session` 会话状态、命令表 `GetCommands()`、各命令处理函数、帮助 |
| `toolgplat/creation.h/.cpp` | 创建 tag / 队列，从脚本文件、s7ioserver 配置文件批量创建 tag |
| `toolgplat/display.h/.cpp` | 显示 tag 值、board 信息、类型列表 |
| `toolgplat/text_util.h` | `ToLower`、`ToUpper`、`Trim`、`StripComment`、`SplitWords`、`SplitAndTrim`、`ParseInt` |
| `toolgplat/type_handle.h` | 内置类型表、类型描述符构造、S7 类型映射 |

- 模块之间只通过连接句柄 `int conn` 交互，`creation` / `display` 不依赖 `Session`。
- `toolgplat.vcxproj` 已加入新文件；Makefile 使用通配符，无需修改。

## 4. 主要改动

### 4.1 会话与命令分发（main.cpp）

- 用 `Session` 结构体（`conn`、`host`、`boardOpened`、`running`）替代 `g_hConn`、`g_qbdtype`、`GlobalObj`，提示符由 `Session::Prompt()` 生成。
- 命令表 `std::vector<Command>`，每项包含：名称及别名、处理函数、帮助文本。新增命令只需加一行；`help` 列表和 `help <cmd>` 均由命令表生成。
- `exit` / `q` 也作为普通命令（设置 `session.running = false`）。
- 公共前置检查：`RequireConnection`、`RequireBoard`、`RequireWords`。

### 4.2 创建（creation.cpp）

- `ElementType { name, code, size }` 统一描述元素类型：
  - `ResolveTagType`：解析 `内置类型名 | String | 已注册 struct 名 | 类型名$大小`；
  - `ResolveStructType`：tag 与队列共用。
- `CreateTag` 只保留一条流程：解析类型 → 检查大小 → 构造描述符 → `createtag` → 输出结果。
- 对外接口：`CreateTagFromWords`（命令行与脚本文件共用同一语法解析）、`CreateQueue`、`CreateTagsFromScriptFile`、`CreateTagsFromConfigFile`。
- 常量：`kMaxDataSize = 16000`、`kDefaultS7StringLength = 254`。

### 4.3 显示（display.cpp）

- `PrintTag` 读取类型描述符后分派到 `PrintSimpleTag`、`PrintStringTag`、`PrintStructTag`。
- 递归 `PrintFields` 统一处理普通字段、数组字段、嵌套 struct（及其数组），缩进与原输出一致。
- `PrintElements`（`[a, b, c]` 格式）、`PrintWriteTime`、`ReadTagData`、`PrintReadError` 消除重复。

### 4.4 类型（type_handle.h）

- `TypeInfo` 增加 `name` 字段，内置类型只保留一张表 `GetBuiltinTypes()`，`FindTypeByName` / `FindTypeByCode` 基于它查找。
- 删除与 `PrintValue<char>` 等价的 `PrintChar`；`PrintString` 更名为 `PrintPodString`。
- 新增类型描述符定义：`kStructTypeCode = -1`、`TypeDescriptorHeader`、`BuildTypeDescriptor()`。
- `GetS7TypeMap` 与 `MapS7Type` 合并为 `MapS7Type`。

## 5. 顺带修复的缺陷

| 问题 | 修复 |
|---|---|
| `select` / `delete` 不带参数时访问 `words[1]` 越界 | `RequireWords` 检查参数个数 |
| 类型名过长时 `strcpy` 写入 `char buff[128]` 溢出 | 描述符改用 `std::vector<char>` 构造 |
| 未连接时执行 board 命令，向 fd 0 发送请求 | 先检查连接和 board 是否已打开 |
| 配置文件中 STRING 未指定最大长度时，本应提示却因条件写错成为死代码，实际创建 1 字节 tag | 缺省按 254 创建，与 s7ioserver 一致；长度非法时跳过并提示 |
| 读取字符串 tag 使用固定 4096 缓冲区，长字符串读取失败 | 按 tag 容量 + 1 分配 |
| `PrintHex` 设置 `setfill('0')` 后未恢复，影响后续输出 | 打印后恢复原填充字符 |
| `atoi` / `stoi` 解析数字：非法输入抛异常或被静默当作 0 | 统一使用 `ParseInt`（`std::from_chars`），非法时给出提示 |
| `help create` 中队列示例使用 `Int32`，与"队列只支持 struct"矛盾 | 示例改为 `SensorData` |
| `desc` 两行都显示 "tag count" | 区分为 `Tag count (head)` / `Tag count (active)` |
| deletetag、clearb、readtype、readb 失败时无任何提示 | 输出失败信息及错误码 |

## 6. 行为变化

- 输出文字统一为 `Tag 'x' created: Int32[3], 12 bytes.` 等格式，失败信息都带错误码。
- 简单类型数组 tag（如 `Int32 10`）在 `select` 时显示所有元素，原来不输出任何内容。
- 参数校验更严格：数组大小须为非负整数，队列记录数须为正整数；脚本行多余的参数不再被忽略，而是报错。
- `open` 需要先 `conn`；重新 `conn` 后 board 状态复位为未打开。
- `create queue` 只需连接，不需要打开 board。
- `main.cpp` 去掉了 UTF-8 BOM（g++ 编译不受影响）。

## 7. 验证

- `make toolgplat` 编译通过，`-Wall -Wextra` 无警告。
- 对本机运行中的 gplat 服务端测试：`help`、`conn`、`open`、创建内置类型 / 数组 / String / struct / `类型名$大小` 的 tag、非法参数、超大小、脚本与配置文件批量创建、`select`（标量、数组、字符串、嵌套 struct 数组、PodString 数组）、`create queue` 非法类型与非法记录数、`desc`、`types`、`delete`，结果符合预期；测试 tag 已删除。
