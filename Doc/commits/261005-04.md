# 20261005-04 客户端 fd 所有权：库不再关闭调用方的 fd

完成 [20261005-03](20261005-03.md) 第六节遗留的第 4 项，并一并修复该节列出的三个相关缺陷。用户确认的三项决策：

| 决策 | 选择 |
|---|---|
| fd 所有权方案 | 方案 B + C 全部：库永不 close 调用方 fd；同时修 readn EOF、`MSG_NOSIGNAL`、`ERROR_BUFFER_TOO_SMALL` 读掉包体保留连接、`subscribe` / `waitpostdata` / `registertag` 服务端错误不再断开 |
| s7ioserver 失败处理 | 读写线程都只在 CONNECTION 类错误时 `disconnectgplat` 并重连，其它错误记日志后继续；写线程注册阶段失败仍关闭并重连 |
| `connectgplat` 的打印 | 改为经错误钩子上报一次（附 host:port），去掉 `unblock_connect` 的 stdout 打印，所有失败路径正确设置 errno |

## 一、新约定

网络 API 从不 `close` 调用方的 fd（只有 `disconnectgplat` 关闭）。字节流不可再信任时只 `shutdown(SHUT_RDWR)`，并返回 CONNECTION 类错误码：

| 情形 | 错误码（类别） | 连接 |
|---|---|---|
| send / recv 失败 | errno（CONNECTION） | shutdown |
| 对端关闭，响应没收完（EOF） | `ERROR_SOCKET_NOT_CONNECTED`（CONNECTION） | shutdown |
| 响应错位：不该有包体却有、`id` 不符、包体长度不符、`bodysize` 越界 | `ERROR_INVALID_RESPONSE`（CONNECTION） | shutdown |
| 包体比调用方缓冲区大 | `ERROR_BUFFER_TOO_SMALL`（USAGE） | 包体读掉丢弃，保留 |
| 服务端返回的错误（含 `subscribe` 不存在的 tag） | 原错误码 | 保留 |
| 客户端参数校验失败 | `ERROR_INVALID_PARAMETER` 等（USAGE） | 未发送，保留 |

于是"类别为 CONNECTION"与"连接已不可用"完全等价，调用方和 `GplatConnection` 只需看类别，不必再按错误码猜测库是否关闭了 fd。

选择 shutdown 而不是什么都不做：

- fd 号保持有效，直到调用方 `disconnectgplat`，不会出现"库关一次、调用方又关一次"的重复关闭，也不会在多线程下误关别的线程新打开的同号 fd。
- 服务端立即收到 FIN，断开并清理订阅；即使调用方忘了关闭 fd，服务端资源也不会滞留。
- 之后在该 fd 上的调用发送即失败（`EPIPE`，CONNECTION 类），不会把残留字节当成下一个响应解析。

## 二、修改

### libhigplat（`higplat/higplat.cpp`）

- `send_all`：`send` 加 `MSG_NOSIGNAL`（对端断开时返回 `EPIPE`，不再以 SIGPIPE 杀死进程），`EINTR` 时重试。
- 新增文件内 helper：
  - `fail_connection(sockfd, error, code)`：置错误码并 `shutdown(SHUT_RDWR)`，返回 false。
  - `send_request` / `recv_response`：收发失败或短读时调用 `fail_connection`；`recv_response` 要求收满，EOF 报 `ERROR_SOCKET_NOT_CONNECTED`。`readn` 本身不变（EOF 返回短计数）。
  - `discard_body`：包体比缓冲区大时分块读掉并丢弃，报 `ERROR_BUFFER_TOO_SMALL`；`bodysize` 为负或超过 `MAXMSGLEN` 视为响应错位。
- 24 个网络函数中的 89 处 `close(sockfd)` 全部换成上述 helper：80 处为固定模式（send/recv 失败、`ERROR_INVALID_RESPONSE`、`ERROR_BUFFER_TOO_SMALL`），用脚本替换；9 处手工修改（`subscribe`、`waitpostdata`、`getresponse`、`registertag` 中带长度校验的 `readn` 和服务端错误时的 close）。保留的 `close` 只有 `unblock_connect` 关闭它自己创建的 socket（2 处）和 `disconnectgplat`。
- `subscribe` / `registertag` / `waitpostdata`：服务端错误只返回错误码，不再断开连接；`waitpostdata` 缓冲区不足时丢弃这条事件，订阅保留。
- 错误上报：从 `AutoErrorCheck` 析构函数中抽出 `ReportError(error, func, message)`；`connectgplat` 失败（参数非法为 `ERROR_INVALID_PARAMETER` + `EINVAL`，否则为 errno）经它上报一次，`message` 形如 `Connection refused (127.0.0.1:8777)`。
- `unblock_connect`：去掉 6 处 `printf`（其中 "connect with server immediately" 在连接成功时也会打印）；poll 超时置 `ETIMEDOUT`，异步失败置 `SO_ERROR` 的值，`close` 前后保存 errno（改动前 errno 可能是过期值，实测失败信息为 "Operation now in progress"）。`connectgplat` 去掉 `setblocking` 后从不触发的警告打印。

### 头文件与 C++ 封装

- `include/higplat.h`：Network API 前加 fd 所有权说明；`ERROR_BUFFER_TOO_SMALL`、`GPLAT_ERRCAT_CONNECTION` 的注释改为新语义；钩子说明增加 `connectgplat`。
- `higplat/qbd.h`：`ErrorCategory::Connection` 注释。
- `include/gplat_connection.h`：删除 `CloseRule` 和 `closed_by_library`；`call()` 遇到 CONNECTION 类错误时先构造异常，再 `close()` 自己的 fd，然后抛出 `GplatConnectionError`；USAGE 抛 `GplatUsageError`（连接保留）；RESULT 只返回码。

### 调用方

| 文件 | 修改 |
|---|---|
| `s7ioserver/threadWritePlc.cpp` | `waitpostdata` 失败：CONNECTION 类时 `disconnectgplat` 后重连，其它错误记 error 日志后继续；初始注册和重连后注册失败时先 `disconnectgplat` 再重试 |
| `s7ioserver/threadReadPlc.cpp` | `writeb` 失败：CONNECTION 类时 `disconnectgplat` 后重连（修复旧 fd 泄漏），其它错误（tag 不存在、大小不符）记 error 日志后继续下一个 tag，不再反复断开重连；线程退出时关闭 gPlat 连接 |
| `toolgplat/monitor.cpp` | `subscribe` 失败和接收线程 `join` 之后由主线程 `disconnectgplat`；顺带消除了 260929-02 记录的"主线程可能对已被库关闭的 fd 调用 shutdown"的竞态 |

无需修改、但行为随之变正确的调用方：toolgplat 主会话（以前库关闭 fd 后，`conn` 命令和退出时会再关一次失效的 fd 号）、testsuite `test_getresponse` 的响应线程（`subscribe` / `waitpostdata` 失败后本来就调用 `disconnectgplat`，以前是重复关闭）。

### 对调用方的行为变化

| 场景 | 改动前 | 改动后 |
|---|---|---|
| 对端关闭后调用 `readb` 等 20 个只判断 `readn() < 0` 的函数 | 返回成功、`error = 0`，输出缓冲区未写入 | 返回 false，`ERROR_SOCKET_NOT_CONNECTED` |
| 连接已断开后再调用 | 进程被 SIGPIPE 杀死 | 返回 CONNECTION 类错误（如 `EPIPE`） |
| I/O 失败、响应错位 | 库 `close(fd)` | 库 `shutdown`，调用方 `disconnectgplat` |
| `ERROR_BUFFER_TOO_SMALL` | 库 `close(fd)`；`GplatConnection` 抛 `GplatUsageError` 且 `is_open()` 为 false | 包体读掉丢弃，连接保留；`GplatConnection` 抛 `GplatUsageError`，`is_open()` 为 true |
| `subscribe` 不存在的 tag | 库 `close(fd)`；`GplatConnection` 抛 `GplatConnectionError(ERROR_TAG_NOT_EXIST)` | 返回 `ERROR_TAG_NOT_EXIST`，连接和已有订阅保留 |
| `connectgplat` 失败 | `fprintf(stderr)`，`SetErrorHook(NULL)` 关不掉；`unblock_connect` 往 stdout 打印 | 经错误钩子上报一次（默认写一行 stderr）；errno 正确；库不写 stdout |
| 外部 C 调用方依赖"库会关闭 fd" | — | 每次 CONNECTION 类失败泄漏一个 fd（连接已 shutdown，服务端资源已释放），需改为调用 `disconnectgplat` |

## 三、测试与文档

### 测试

- 新增 `testsuite/cases/test_client.cpp`（5 个用例）：
  - `client.peer_close_is_connection_error`：假服务端 accept 后立即关闭；`readb` 必须返回 CONNECTION 类错误，再次调用不被 SIGPIPE 杀死，fd 直到 `disconnectgplat` 才关闭。
  - `client.invalid_response_shuts_down`：预先写好一个带包体的写应答；`writeb` 返回 `ERROR_INVALID_RESPONSE`，fd 仍有效，假服务端收到完整请求后读到 FIN，后续调用返回 CONNECTION 类错误。
  - `client.buffer_too_small_keeps_connection`：`waitpostdata`（16 字节缓冲区收 256 字节事件）和 `listq`（1 字节缓冲区）返回 `ERROR_BUFFER_TOO_SMALL`，之后普通请求成功、订阅仍在、下一条事件完整。
  - `client.subscribe_missing_tag_keeps_connection`：订阅不存在的 tag 返回 `ERROR_TAG_NOT_EXIST`，已有订阅照常收到事件，还能继续订阅。
  - `client.wrapper_owns_fd`：`GplatConnection` 遇到对端关闭时抛 `GplatConnectionError`，进程 fd 数回到 `open()` 之前（封装类自己关闭了 fd）；订阅不存在的 tag 只返回码；缓冲区不足抛 `GplatUsageError` 后连接仍可用。
- `testsuite/cases/test_error.cpp` 新增 `error.connect_failure_reported`：连接成功不上报；连接被拒时 errno 为 `ECONNREFUSED`，钩子恰好收到一次（`func` 为 `connectgplat`、CONNECTION 类、`message` 含 host:port）；参数非法时为 USAGE + `EINVAL`；全程 stdout 为空。
- 先在未修改的库上运行这 6 个用例，全部失败，失败原因分别是：EOF 被当成功、库关闭了调用方 fd（3 个用例）、封装类不关闭 fd、`connectgplat` 不经钩子且 errno 为 `EINPROGRESS`。修改后全部通过。
- 用例总数 81 → 87：`testsuite/README.md`（两处，目录清单加 `client`）、`Makefile`（`test-all` 注释与 `help`）。
- `testapp6/main.cpp`：缓冲区不足后断言连接保留、订阅仍能收到下一条事件；`subscribe` 不存在的 tag 断言返回 `ERROR_TAG_NOT_EXIST` 且连接可用；新增 `[6] connection lost`，用本地假服务端验证 `GplatConnectionError`、`is_open()` 为 false 及之后的调用抛 `ERROR_SOCKET_NOT_CONNECTED`。
