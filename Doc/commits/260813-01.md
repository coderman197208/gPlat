**结论**

这次故障分成两层：

1. **初始诱因**：`169.254.201.71` 的 S7 ISO-on-TCP 会话发生接收超时，PLC 的 102 端口或 S7 通信服务短暂不可用。
2. **持续故障的根因**：写线程错误地依赖 `Cli_GetConnected()` 判断连接健康。Snap7 在超时和 `EPIPE` 后仍可能返回“已连接”，导致程序一直使用已经损坏的 socket，永远不会触发重连。重启后重新创建 socket，所以恢复正常。

**日志证据**

- `655470 = 0x000A006E`
  - `0x000A0000`：`errIsoRecvPacket`
  - `0x006E`：Linux `ETIMEDOUT(110)`
  - 即：请求发出后，等待 PLC 响应约 3 秒超时。Snap7 默认接收超时正是 3000 ms。

- `589856 = 0x00090020`
  - `0x00090000`：`errIsoSendPacket`
  - `0x0020`：Linux `EPIPE(32)`，Broken pipe
  - 即：程序继续向已被对端关闭或已经失效的 TCP 会话发送数据。
