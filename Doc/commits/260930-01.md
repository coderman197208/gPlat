# 260930-01 导出创建脚本（export script）

需求来源：[Doc/tasks/20260930-01.md](../tasks/20260930-01.md)

## 1. 需求要点

- toolgplat 创建 tag 和队列成功后，要能保存对应的创建命令，之后用 `export script` 导出，在别的系统上快速重建同样的对象。
- 通过 `create tag from script file` / `create tag from config file` 批量创建的 tag 也要能导出。
- 导出顺序：先队列，后 tag；tag 按名字字母顺序排序。

## 2. 方案确认（两轮提问）

| 问题 | 决定 |
|---|---|
| 创建脚本如何"保存" | 不改 QBD 文件格式。每个 tag 在 `BOARD_INDEX_STRUCT` 中已保存 `itemsize` 和类型描述符，每个队列已保存 `QUEUE_HEAD`（`num` / `size` / `operateMode`）和类型描述符，导出时由这些元数据还原命令。现有 QBD 文件和已存在的对象都能导出 |
| 命令文本形式 | 规范化命令：不保留注释和多余空格；config 文件创建的 tag 导出为 `create <tag> <type>` |
| 导出位置 | toolgplat 客户端本地路径，数据通过网络从服务端获取 |
| 命令语法与作用域 | `export script [fileName]`，任意作用域可用；不带文件名时打印到屏幕；文件已存在时直接覆盖 |
| 网络协议 | 新增 MSGID，分页返回 BOARD 中每个 tag 的原始元数据（名字、`itemsize`、类型描述符），由客户端生成命令文本；服务端不需要了解脚本语法 |
| 队列数据来源 | 复用 `listq` + `readhead` + `readtype`；只导出服务端已载入的队列，不含 BOARD |
| 结构体类型写法 | 本地已注册且大小一致时写 `Vehicle`，否则写 `Vehicle$104` |
| 排序规则 | 队列和 tag 都按名字排序，区分大小写（字节序，大写在前） |
| 无类型描述符的对象（`createb` / `createq` 或直接调用 API 创建） | 以注释行导出，不影响脚本执行 |
| 文件格式 | 加注释头（服务端地址、导出时间、队列 / tag 数量），队列与 tag 之间空一行 |

已知限制：
- 只能导出规范化后的写法：`string 200` 与 `Char 200` 存储相同，一律导出为 `string 200`。
- 分页之间不是同一快照，导出过程中新建或删除的 tag 可能在也可能不在结果里。

## 3. 通信协议与 higplat 库

### 3.1 消息

| MSGID | 处理函数 | 请求 | 响应 |
|---|---|---|---|
| `LISTTAGS` (56，新增) | `HandleListTags` | `qname` = BOARD，`start` = 起始索引槽 | 包体为 `count` 条记录；`start` = 下一页起始槽，`-1` 表示已全部列出 |

`MSGID` 共 52 个，`statusHandler[]` 中有 23 个有效处理函数。

每条记录的格式（不对齐）：`TAG_META{int itemsize; int typesize;}` + 以 `'\0'` 结尾的 tag 名 + `typesize` 字节的类型描述符。`TAG_META` 定义在 `include/higplat.h`，`higplat/qbd.h` 中有一份相同的定义。

### 3.2 网络 API（`include/higplat.h`）

- `listtags(sockfd, start, buff, buffsize, &bytes, &count, &next, &error)`：首次 `start = 0`，之后传入上次的 `next`，直到 `next == -1`。`buffsize` 建议取 `MAXMSGLEN`（16384）。

### 3.3 本地 API（`higplat/higplat.cpp`）

- `ListTags(lpBoardName, start, buff, buffSize, &bytes, &count, &next)`：持有 BOARD 的 `mutex_rw`，从索引槽 `start` 起遍历哈希表，跳过空槽和已删除的项；缓冲区放不下时返回下一页的起始槽。对象不是 BOARD 时返回 `ERROR_OPERATE_PROHIBIT`；`start` 越界时返回 `ERROR_INVALID_PARAMETER`。

## 4. toolgplat

### 4.1 `export script [fileName]`（新增 `export.h/.cpp`）

- `CollectCreateScript`：
  - 队列：对 `listq` 返回并排好序的队列名逐个调用 `readhead` + `readtype` 还原命令。
  - tag：分页调用 `listtags` 读取全部 tag，按名字排序后生成命令。
- `WriteCreateScript`：先写注释头，再写队列命令，空一行后写 tag 命令。
- 先收集全部内容再打开文件，导出失败时不会清空已有文件。

由类型描述符还原命令的规则：

| 存储的类型 | 导出结果 |
|---|---|
| 内置类型 | `create int1 Int32`；数组为 `create Arr Double 5` |
| Char 数组 | `create string2 string 200` |
| 结构体，本地已注册且大小一致 | `create vehicle1 Vehicle`，`create vs Vehicle 3` |
| 结构体，本地未注册或大小不一致 | `create cust Foo$24`，`create cust2 Foo$8 4` |
| 队列 | `create queue vehicle_queue Vehicle 200`，shift 队列末尾加 `shift` |
| 无类型描述符 | `# tag x: no type info, 4 bytes`，`# queue q1: no type info, 104 bytes x 10, shift mode` |
| 有描述符但无法还原（类型码未知、大小不符、队列元素不是非数组结构体） | 同上格式，原因写作 `unsupported type` |

- 描述符中 `arraysize <= 1` 时与 `CreateTag` 一致，按非数组导出。
- 名字含空白时加双引号，`SplitWords` 可以原样读回。
- 注释使用 `#`（`StripComment` 会去掉行内任意位置的 `#`）。

示例输出：

```
# gPlat create script, exported from 127.0.0.1:8788 at 2026-09-30 12:54:17
# 4 queue(s), 9 tag(s)

create queue aq Vehicle 5 shift
create queue cq Foo$16 7
# queue q_notype: no type info, 104 bytes x 10, shift mode
create queue vehicle_queue Vehicle 200

create Arr Double 5
create cust Foo$24
create cust2 Foo$8 4
create int1 Int32
create "my tag" Int16
create string2 string 200
create vehicle1 Vehicle
create vs Vehicle 3
create zeta Int32
```

### 4.2 为了让导出的脚本能重新导入而做的改动（`creation.cpp`）

| 问题 | 修改 |
|---|---|
| `create tag from script file` 只识别 tag 命令，`create queue ...` 行会报用法错误 | 以 `create queue` 开头的行交给 `CreateQueueFromWords` 处理 |
| `create queue` 只接受已注册的结构体，导出的 `Foo$16` 无法导入 | `CreateQueue` 改用 `ResolveTagType`，支持 `<类型名>$<单条大小>`，内置类型和 `string` 仍然拒绝 |
| `CreateQueueFromWords` 在 `main.cpp` 中且没有返回值 | 移到 `creation.cpp`，返回 `bool`，供批量导入统计成功 / 失败 |

### 4.3 其他

- `help create` 中脚本文件的说明改为可同时创建 tag 和队列；新增 `help export`。
- `toolgplat.vcxproj` 加入 `export.cpp/.h`（Makefile 使用通配符，无需修改）。

## 5. 行为变化

- 新 toolgplat 的 `export` 必须连接新服务端：旧服务端对 `LISTTAGS` 不回复，客户端会一直阻塞。
- 脚本文件可以混合写 tag 和队列的 create 命令；仍需在 BOARD 上下文中执行 `create tag from script file`。
- `create queue` 可以使用 `<类型名>$<单条大小>` 形式的自定义类型。

## 8. 遗留事项

- 项目 `bin/` 下正在运行的服务端（8777）仍是旧程序，需要重启后才能使用 `export`。
- 无类型描述符的对象只能以注释导出，需要手工补写创建命令。
- 名字中含 `#` 的对象导出后无法通过脚本重建（`StripComment` 会截断），名字中含双引号的也无法表示。
