# 20261004-04 订阅去重 + P2 事件风暴保护修复

本轮对 gplat 服务端 Pub/Sub 做了两项功能修改，并同步调整了测试套件与文档。

## 一、重复订阅去重

### 问题

同一连接重复订阅同一个 tag 时，服务端不去重：`CSubscribe::Attach` 直接 `push_back`，`ngx_connection_s::Attach` 也直接 `push_back`。写一次 tag，该连接会收到多次事件（DEFAULT 每个节点一次；POST_DELAY 每个节点各起一个延时定时器）。

### 修改

| 文件 | 修改 |
|---|---|
| `gplat/CSubscribe.h` | `Attach(tagname, EventNode)` 插入前查重：DEFAULT 以 `(连接, eventid)` 为键；其余事件（POST_DELAY 等）以 `(连接, eventid, eventname, eventarg)` 为键。`Attach(tagname, void*)` 复用上述重载。补充 `<cstring>`、`<utility>` |
| `gplat/ngx_c_socket.h` | `ngx_connection_s::Attach(tagname)` 同一 tag 名只记录一次（`std::find`），补充 `<algorithm>` |

### 行为

- 同一连接对同一 tag 多次 `subscribe`：写一次只收到 1 个事件。
- 同一连接对同一 tag 用相同 `eventname`/`eventarg` 多次 `subscribedelaypost`：只收到 1 个延时事件。
- 同一 tag 先 DEFAULT 再 POST_DELAY，或 POST_DELAY 的 `eventname`/`eventarg` 不同：仍是独立订阅，各推一次。

## 二、P2 修复：事件风暴保护

### 问题

`NotifySubscriber` 中 `usernumber > 500` 时直接 `exit(1)`，会打垮整个 server：

1. 合法的大量订阅者（>500 个连接）也会触发。
2. 它防不住真正的风暴（订阅者收到事件后又写同一 tag，事件相互放大）。真正失控的是每连接待发事件队列 `m_listPost` 的无界积压（也是 P3 的成因）。

### 方案（用户确认）

- 删除订阅者数量检查及 `exit(1)`，不限制订阅者数量。
- 给每个连接的 `m_listPost` 设上限，默认 1000，可配置。
- 队列满后**丢弃最新事件**（队列里已有事件不动），限频记日志。

### 修改

| 文件 | 修改 |
|---|---|
| `gplat/ngx_c_slogic.cxx` | 删除 `usernumber > 500` 的 `exit(1)`；4 处 `m_listPost.push_back` 全部改为 `EnqueuePost`：`NotifySubscriber` 的 DEFAULT 分支、POST_DELAY 定时回调、`NotifyTimerSubscriber`、PLC IO 服务器分支 |
| `gplat/ngx_c_socket.h` | `ngx_connection_s` 新增 `EnqueuePost(char*, const char* tagname)`、`s_maxPendingPost`（`inline static std::atomic<int>`，默认 `kDefaultMaxPendingPost = 1000`）、`m_droppedPost`、`m_lastDropLog` |
| `gplat/ngx_c_socket_conn.cxx` | 实现 `EnqueuePost`：未满则入队；已满则释放新包、累计丢弃数，同一连接每 5 秒最多记一条 WARN 日志（含 tag 与累计丢弃数）。`GetOneToUse` 重置计数 |
| `gplat/ngx_c_socket.cxx` | `ReadConf` 读取 `Sock_MaxPendingPost`，`<=0` 回退默认值 |
| `config/gplat.conf` | 新增 `Sock_MaxPendingPost = 1000` 及注释 |

调用约定：`EnqueuePost` 须在持有该连接 `logicPorcMutex` 时调用（与原 `push_back` 一致，锁顺序不变）。

### 取舍

- 队列满后丢弃最新事件：慢消费者或失控订阅者会丢失满队列之后的事件；内存有界、服务不崩。
- 风暴期间的 CPU 开销（遍历订阅者、分配包）不变，本方案只保证内存有界和服务存活。
- P3（只订不取导致 `m_listPost` 无界堆积）随之变为有界。
