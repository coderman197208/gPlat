# gplat请求响应功能的实现

## 需求
gplat客户端把请求数据写入gplat，另一个客户端通过订阅的方式接收请求数据，处理后把响应数据写回gplat，最后发出请求的客户端收到响应数据。

## 术语
请求数据 request
响应数据 reponse
请求数据的C结构体类型 Request
响应数据的C结构体类型 Reponse

## API接口

### 定义
```c
extern "C" bool getresponse(int sockfd, const char* request_tag, void* request_value, int request_size, const char* response_tag, void* response_value, int response_size, unsigned int* error);
```
sockfd gplat连接的文件描述符
request_tag 请求数据的tag名字
request_value 请求数据的内存地址
request_size 请求数据的内存大小
response_tag 响应数据的tag名字
response_value 接收响应数据的内存地址
response_size 响应数据的内存大小
error 返回的错误码

### getresponse内部实现
- 发出请求：通过writeb写入request_tag，值为request_value
- 然后订阅response_tag事件
- 通过waitpostdata等待response_tag事件
- response_tag事件到来后，把响应数据复制到response_value
- getresponse函数返回

### 注意事项
- 调用getresponse前，sockfd连接可能已经订阅了其它tag，**因此调用waitpostdata接收响应数据的时候gplat应禁止向此连接推送除response_tag外的其它事件**，否则将使程序崩溃，其它事件应在gplat侧排队，getresponse完成后再向客户端推送
- request和reponse应该一一对应，也就是说，对于同名request(request_tag相同)，在任何时刻gplat服务侧只能处理1个，否则将多次推送reponse使程序崩溃，当出现此情况，gplat应阻塞后面的请求，待前面的请求完成后再继续处理
- getresponse函数应考虑响应超时问题，默认超时时间2秒，gplat侧需丢弃没有客户端等待的reponse，记录到日志
