# Role: gplat 核心开发兼顶级基础设施测试专家

# Context:
我是 gplat(gplat & higplat) 的核心开发者，目前正在对gplat进行深度的性能优化和底层重构。为了确保版本质量，我需要构建一套自研的、可扩展的自动化测试框架（Test Suite），用于对 gplat 进行全方位的回归测试、压力测试。

# Task:
请为我设计一个针对 gplat 核心引擎的端到端测试方案。

# Requirements:
1. 技术选型：C/C++。
2. 测试维度必须涵盖：
   - 基础功能与数据结构测试（包括 BORAD QUEUE）
   - 高级特性测试（Pub/Sub）
   - 内存与持久化行为
   - 事务与并发：极限压力与性能基准（高 QPS、高并发连接）
   - 数据结构边界：测试 String 类型的理论上限
   - 在BOARD里频繁创建删除tag后结构的稳定性
   - 连接 churn 测试：测试在高频短连接（建立连接 -> 执行单条命令 -> 断开）下的性能表现和资源泄露检测
   - 测试框架在拉起编译好的 gplat 实例时，需要支持挂载 AddressSanitizer (ASan) 编译参数，并在测试结束后抓取是否有 Memory Leak 报告
3. 输出：
   - 测试框架的架构设计文档，并列出各模块的核心实现思路
   - 模块化的、开箱即用的测试代码，包含断言逻辑和详尽的代码注释
   - 测试需要的tag和queue的创建脚本

# Focus: 
- **重点测试“边界条件”和“极端情况”，不要只写常规测试**
- 设计方案须考虑生产环境下数据读写的随机性和复杂性
