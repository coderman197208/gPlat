## 0. 设计总纲

| 原则 | 落地方式 |
|---|---|
| 与生产实例完全隔离 | 每次测试自建 sandbox 目录树 + 独立端口（默认 18777，可自动探测空闲端口），**绝不触碰仓库 `qbdfile/` 和 8777 上的实例** |
| 重点覆盖边界/极端 | 每个 API 配一张"正常 / 边界 / 非法 / 极端"四象限用例矩阵（见第 7 节），常规路径只占少数 |
| 可复现的随机性 | 压力负载用**带种子的 PRNG**，失败时打印种子即可精确重放；记录序列号 + CRC32 校验数据完整性 |
| 真实缺陷不污染回归 | 命中已知缺陷的用例标 `XFAIL(缺陷ID)`，套件整体仍绿；缺陷被修复后变 `XPASS` 提醒更新登记表 |
| ASan/LSan 开箱即用 | `make ASAN=1` 把 gplat + higplat 编到 `build/asan/{bin,lib}`，启动器注入 `ASAN_OPTIONS`，teardown 抓 `asan.<pid>` 报告 |
| 崩溃不拖垮套件 | 预期崩溃的用例在 **子进程 fork 隔离** 中运行，父进程只判定退出码/信号；server 每个破坏性用例后重启 |

## 2. 构建与 ASan 集成（Makefile 改动清单）

仿照 `TESTAPP7` 的模块样板，新增 `TESTSUITE` 模块；新增 `ASAN` 开关生成隔离构建树。

**2.1 新增 ASan 变体（利用现有空钩子 `CXXFLAGS_PLATFORM`/`LDFLAGS_PLATFORM`）**

```makefile
# make ASAN=1 时：开启 ASan，并把产物输出到 build/asan/{bin,lib}，保持 bin 与 lib 同级以满足 $ORIGIN/../lib
ifeq ($(ASAN),1)
    CXXFLAGS_PLATFORM += -fsanitize=address -fno-omit-frame-pointer -O1
    LDFLAGS_PLATFORM  += -fsanitize=address
    BUILD_DIR := build/asan
    BIN_DIR   := build/asan/bin
    LIB_DIR   := build/asan/lib
endif
```

- 关键点：`BIN_DIR`/`LIB_DIR` 必须同级，因为所有可执行用 rpath `$ORIGIN/../lib`；`build/asan/bin` + `build/asan/lib` 满足。
- 常规（非 ASan）构建完全不变，输出仍在 `bin/`、`lib/`。
- 基准/趋势类用例默认用**非 ASan** 构建跑（ASan quarantine 会抬高 RSS、拖慢吞吐）；泄漏判定用例用 ASan 构建跑。

**2.2 新增 TESTSUITE 模块块**（插在 TESTAPP7 块后）

```makefile
TESTSUITE_DIR      := testsuite
TESTSUITE_SRCS     := $(wildcard $(TESTSUITE_DIR)/*.cpp) \
                      $(wildcard $(TESTSUITE_DIR)/framework/*.cpp) \
                      $(wildcard $(TESTSUITE_DIR)/cases/*.cpp)
TESTSUITE_OBJS     := $(patsubst $(TESTSUITE_DIR)/%.cpp, $(BUILD_DIR)/$(TESTSUITE_DIR)/%.o, $(TESTSUITE_SRCS))
TESTSUITE_BIN      := $(BIN_DIR)/testsuite
TESTSUITE_INCLUDES := -Iinclude
TESTSUITE_LDFLAGS  := -lpthread -L$(LIB_DIR) -lhigplat -Wl,-rpath,'$$ORIGIN/../lib'
```

**2.3 需同步追加的位置**（与 TESTAPP7 完全对应）：`.PHONY`、`all:`、`testsuite:` 目标、链接规则、编译规则（注意 `cases/`、`framework/` 子目录 `mkdir -p $(@D)` 已覆盖）、`clean`、`help`、`-include $(TESTSUITE_OBJS:.o=.d)`。

**2.4 新增便捷伪目标**

| 目标 | 作用 |
|---|---|
| `make testsuite` | 编译套件（常规构建） |
| `make test` | 跑常规回归（不含破坏性用例） |
| `make test-asan` | `make ASAN=1` 编 gplat/higplat/testsuite，再以 ASan 实例跑泄漏相关用例 |
| `make test-destructive` | 单独跑破坏性用例（每用例 fork + 重启 server） |
| `make test-stress` | 跑基准（非 ASan、可选 `-O2` 变体） |

## 3. 测试框架核心

**3.1 注册表与用例模型**

```cpp
// 每个用例：名字 + 标签位 + XFAIL 缺陷ID（0 表示预期通过）+ 函数指针
struct TestCase {
    const char* name;
    uint32_t    tags;        // BOARD|QUEUE|PUBSUB|STRESS|DESTRUCTIVE|ASAN|...
    int         xfailBug;    // 命中已知缺陷则填登记表ID，否则 0
    void      (*fn)(TestContext&);
};
#define TEST(name, tags)              /* 注册一个预期通过的用例 */
#define TEST_XFAIL(name, tags, bugid) /* 注册一个命中已知缺陷、预期失败的用例 */
```

- 运行器按 `--filter`（名字子串）/`--tag`（标签）筛选；`--list` 只列不跑；`--seed N` 固定随机种子。
- 结果分类：`PASS / FAIL / XFAIL（预期失败且确实失败）/ XPASS（登记为缺陷却通过了 → 需复核登记表）/ SKIP`。
- 退出码：有 `FAIL` 或 `XPASS` → 非 0；全 `PASS/XFAIL/SKIP` → 0。

**3.2 断言宏**（沿用 testapp5/7 的 `CHECK` 观感，增强为可中止 + 错误码专用）

```cpp
CHECK(cond, fmt, ...)        // 记录失败并继续（软断言）
ASSERT(cond, fmt, ...)       // 失败即 longjmp 结束本用例（硬断言，防止后续解引用崩溃）
EXPECT_OK(call, err)         // 期望 API 返回 true 且 err==0
EXPECT_ERR(call, err, code)  // 期望 API 返回 false 且 err==code（边界/非法用例主力）
```

**3.3 fork 隔离执行器**

- 预期打崩 server 或打崩客户端库的用例，在子进程里跑：`pid=fork()`，子进程执行用例体，父进程 `waitpid` 判定 `WIFSIGNALED`（如 SIGSEGV）或退出码，并与"期望的崩溃形态"比对。
- 这样 `createtag(负 tagsize)` 把 server 打崩、`FD_SET(fd>=1024)` 把客户端打崩，都不会带走整个测试进程。

## 4. Server 启动器 / Sandbox（`server_fixture`）

**4.1 Sandbox 目录树**（每个 server 实例一棵，建在 `mkdtemp` 临时目录）

```
<tmp>/gplat_sbx_XXXX/
├── bin/           # gplat 的工作目录（cwd），配置/qbd/logs 都相对它定位
│   └── gplat      # 从 bin/ 或 build/asan/bin/ 硬链接/拷贝过来
├── lib/           # libhigplat.so（满足 rpath）
├── config/gplat.conf   # 本套件生成：端口、Daemon=0、worker_connections、RecyWait、线程数可调
├── qbdfile/       # 测试需要的 BOARD/QUEUE，预先用 createb/createq 或本地 API 生成
└── logs/
```

**4.2 配置生成**：按用例需要写 `config/gplat.conf`。关键项：
`ListenPort0=<动态端口>`、`Daemon=0`（前台，便于直接拿 worker pid 和退出）、`Sock_RecyConnectionWaitTime`（churn 用例调小到 1~2s 加速回收、或调大观察池增长）、`ProcMsgRecvWorkThreadCount`（发送路径/并发用例需 ≥2）、`worker_connections`（池增长用例设小以观察无界增长）。

**4.3 启停时序**（已核对源码）
- 启动：`fork`，子进程 `chdir(sandbox/bin)` 后 `execl(gplat)`；父进程**轮询连接端口直到成功**（worker init 有 `sleep(1)`，启动至少 1s，设 10s 上限）；stdout/stderr 重定向到 `logs/stdout.log`（定时器每 500ms 打印中文行，不影响）。
- 关闭：`SIGTERM` 发给 **master**（worker 的信号处理器是空的，必须发 master）；`waitpid` 等 master 退出；worker 退出时 LSan 在 worker 内运行。
- ASan：`setenv ASAN_OPTIONS = detect_leaks=1:log_path=<sandbox>/asan:abort_on_error=0:detect_stack_use_after_return=1`，使泄漏写到 `asan.<pid>`；teardown 解析 master 与 worker 两个文件。

**4.4 ASan 报告判定**
- 解析 `asan.*`：区分 **Direct/Indirect leak**（LSan）与 heap-overflow/use-after-free（ASan 错误）。
- 对 leak，先减去"**基线泄漏**"（见第 5 节）再判定；ASan 内存错误一律即时 FAIL（除非该用例 XFAIL 登记了对应缺陷，如协议错位引发的越界读）。

## 5. 泄漏判定策略（关键，避免误报）

gplat 存在**关闭时、带在连接客户端**的"逻辑泄漏"（`m_listPost` 里的 `char*`、`precvMemPointer`/`psendMemPointer` 在 `clearconnection` 走析构但不释放缓冲），LSan 会如实报告。必须把它与"运行期真实泄漏"分开：

1. **基线法**：先跑一个"空闲 + 正常连接后干净断开 + 正常 SIGTERM"的基线实例，记录其 LSan 指纹（调用栈特征）。真实用例的报告**减去基线指纹**后若仍有残留 → 真实泄漏 FAIL。
2. **抑制文件**：对已知的 shutdown-leak 写 `lsan.supp`（`LSAN_OPTIONS=suppressions=...`），并在登记表标注；这样默认不报，但用例可显式取消抑制来验证"修复后应消失"。
3. **趋势法（针对 reachable 但无界增长，LSan 看不到）**：`proc_sampler` 周期采样 worker 的 `VmRSS/VmHWM`（`/proc/<pid>/status`）和 fd 数（`/proc/<pid>/fd` 计数），做"稳态后斜率"判定——
   - `m_mapResponseOwner` 永不清理、连接池 `ngx_get_connection` 无界增长、`m_listPost`/定时器订阅堆积，都属此类。
   - 判据：负载稳定段 RSS/fd 斜率应 ≈ 0（给定容差）；持续单调上升 → 标记（多为 XFAIL 登记项）。趋势类**用非 ASan 构建**（避免 quarantine 抬高 RSS 干扰斜率）。

## 6. 白盒 BOARD 结构校验器（`board_inspector`）

频繁建删后，直接 `mmap` sandbox 的 BOARD 文件，按 `BOARD_HEAD`/`BOARD_INDEX_STRUCT` 布局校验不变量：

- **索引计数**：`indexcount` == 实际非空且未 erased 的槽数。
- **数据区紧致**：所有存活 tag 的 `[startpos, startpos+itemsize)` 恰好无缝平铺 `[0, nextpos)`，无重叠无空洞；`remain == totalsize - sizeof(BOARD_HEAD) - nextpos`。
- **类型区紧致**：`[typeaddr, typeaddr+typesize)` 平铺 `[0, nexttypepos)`；`typeremain` 一致。
- **探测可达性**：对每个存活 tag，用与 `hash1/hash2` 相同的探测序列必须能定位到它本身（删除后墓碑不应截断同簇其它 tag 的探测链）。
- **无重复**：不存在两个存活槽同名。
- **墓碑统计**：报告 `erased==true` 的残留槽数与剩余空槽数（逼近 `INDEXSIZE-1` 时预警探测退化/死循环风险）。
- **影子模型对比**：用例维护一张 `map<name, bytes>` 影子表，逐 tag `readb` 比对值，确保建删搬移（`DeleteItem` 的 `memmove`）没有损坏邻接 tag 数据。

## 7. 用例矩阵（逐 API × 四象限，重边界/极端）

> 记号：**[N]** 正常 **[B]** 边界 **[I]** 非法入参 **[X]** 极端/破坏性（默认不跑，`test-destructive`）。命中已知缺陷者标 `XFAIL#id`。

### 7.1 BOARD — `writeb/writeb_notpost/readb`
- [N] 各标量/数组/结构体 tag 的写后读回，值与时间戳正确；`writeb_notpost` 不触发订阅、`writeb` 触发。
- [B] `actsize` 恰等于 tag `itemsize`（唯一合法）；`actsize==16384` 的满包；时间戳指针为 NULL。
- [B] `actsize != itemsize` → `ERROR_RECORDSIZE`（server 端 `WriteB/ReadB` 严格等长）。
- [I] `tagname=NULL`/`value=NULL`/`actsize<=0` → `ERROR_INVALID_PARAMETER`；`actsize>16384` → `ERROR_PARAMETER_SIZE`。
- [I] 读/写不存在 tag → `ERROR_TAG_NOT_EXIST`。
- [B] `readb` 的 `actsize` 大于 tag 实际 → 服务端按 datasize 组织，验证 `BUFFER_TOO_SMALL`/等长语义边界。
- [X] `readb` 请求头 `datasize` 与实际 tag 不一致导致的**堆上多读**（裸协议构造，XFAIL 登记）。

### 7.2 BOARD — `createtag/deletetag`
- [N] 建 tag（带/不带类型描述符）→ 写读 → 删 → 再读应 `TAG_NOT_EXIST`。
- [B] `typesize` 恰 100；tag 名恰 39 字符；填满剩余空间的最后一个 tag；建到第 7176 个（`INDEXSIZE-1`）后再建 → `ITEM_OVERFLOW`。
- [B] 名字 >39 字符被静默截断 → 构造两个前 39 字符相同的名字验证**别名**冲突行为。
- [I] `typesize>100` → `ERROR_PARAMETER_SIZE`；`tagname/type=NULL` → `INVALID_PARAMETER`。
- [X] `typesize==0`：现实现**永远失败并 close(socket)** → `XFAIL#C1`。
- [X] `tagsize` 为负：server `memset` 超大长度**崩溃** → fork 隔离 + `XFAIL#C2`。
- [X] `typesize` 为负：客户端越界读 + 服务端流错位 → `XFAIL#C3`。
- [B] 等字符和/字谜名字（相同探测序列）批量建删，交给白盒校验器验结构。

### 7.3 BOARD — `readb_string/writeb_string/writeb_string_notpost/clearb`
- [N] 写入变长字符串、读回长度正确；`clearb` 后 tag 清零。
- [B] 字符串长度恰等于 tag 容量（**无 `\0` 余量**）：验证 `readb_string` 的结尾处理（`bodysize==buffersize` 时写 `value[buffersize-1]='\0'`，会截断最后一字节 → 记录语义）。
- [B] 空字符串（len 0）写读。
- [I] `value=NULL` → `writeb_string` 崩溃（现实现未判空）→ fork + `XFAIL#C4`；`strlen>16384` → `PARAMETER_SIZE`。
- [B] 字符串超过 tag `itemsize` → `STRING_TOO_LONG`。

### 7.4 QUEUE — `writeq/readq/clearq/peekq`
- 覆盖 **NORMAL × {ASCII,BINARY}** 与 **SHIFT × {ASCII,BINARY}** 四组（ASCII 队列 CLI 不支持，用本地 API 预建）。
- [N] NORMAL：FIFO 顺序、容量 `num-1`、写满 → `DQ_FULL`、空读 → `DQ_EMPTY`。
- [N] SHIFT：覆盖最旧、`readq` 返回最新且不消费。
- [B] BINARY `actsize != size` → `RECORDSIZE`；ASCII 读 `actsize<size`/写 `actsize>size` → `RECORDSIZE`；ASCII `writeq(actsize=0)` 走 `strlen+1` 分支。
- [B] `peekq` 的 `PEEK_NEXT`/`PEEK_LATEST` 在空队列 → `DQ_EMPTY`；`actsize` 边界；`position` 非法 → `INVALID_PARAMETER`；peek 不改变读写指针（与 readq 交叉验证）。
- [I] `qname=NULL`、`record=NULL`、`error=NULL`（`clearq(error=NULL)` 崩溃 → `XFAIL#C5`）。
- [B] 网络建队列（`createqueue`）恒为 BINARY；`recordsize>2048` 或 `typesize>100` → `PARAMETER_SIZE`。
- [N] `readhead`/`listq` 读队列头与已加载队列名。

### 7.5 String 理论上限
- 逐步逼近 `MAXMSGLEN=16384`：16383 / 16384 / 16385（后者 `PARAMETER_SIZE`）。
- 构造 tag `itemsize` 分别为 1、16384 的字符串 tag，测"恰满"与"溢出一字节"。
- 服务端 `bodysize` 为 `unsigned short`：构造使 body==65536 截断为 0（裸协议）→ 验证 0 长 body 立即派发 → `XFAIL#S1`。
- `e_pkgLen>16384`：server 丢头但不关连接 → 流错位 → `XFAIL#S2`（破坏性，裸协议）。

### 7.6 Pub/Sub — `subscribe/waitpostdata/subscribedelaypost`
- [N] 订阅 → 另一连接 `writeb` → `waitpostdata` 收到 tagname+数据；`writeb_notpost` **不**触发。
- [B] `waitpostdata` 超时：`timeout=0` 立即 `WAIT_TIMEOUT`；`timeout>0` 定时；`timeout=-1` 永久等待（用例设看门狗避免挂死）。
- [B] `tagnamesize<40` / `buffersize<=0` / `timeout<-1` → `INVALID_PARAMETER`；超时返回 tagname 为 `"WAIT_TIMEOUT"`。
- [N] `subscribedelaypost`（POST_DELAY）：延迟 `delaytime` ms 后投递；验证 eventname 回传。
- [B] `delaytime` = 0 / 负 / 极大，观察 `g_tm.add_once` 行为（0/负→至少 1ms；极大→不触发窗口内）。
- [B] 订阅不存在的 tag、未知 eventid：server 接受不校验 → 记录语义（`XFAIL#P1`）。
- [B] 同连接重复订阅同 tag（无去重）→ 投递重复份数。
- [X] **单连接订阅 501 次** → 一次 `writeb` 触发 `NotifySubscriber` `usernumber>500` → server `exit(1)` → fork + 重启 + `XFAIL#P2`。
- [内存] 只订阅不 `waitpostdata`，持续 `writeb` → `m_listPost` 无界增长（趋势法，`XFAIL#P3`）；定时器订阅（5 个周期定时器）从不 drain 同理。

### 7.7 getresponse（请求/响应）
- [N] 请求方 `getresponse` 阻塞 → 响应方 `subscribe` 请求 tag、`waitpostdata` 收到、`writeb(response_tag, start=1)` 回写 → 请求方拿到响应。
- [B] 并发等待排队：1 个 active + 64 个 waiting（`REQUEST_QUEUE_MAX=64`）均正常；再来第 66 个请求（即第 65 个试图进入等待队列者）→ `REQUEST_QUEUE_FULL`。
- [B] `timeout_ms<=0`、req/resp tag 相同、`request_size!=实际`、`response_size>16384`、tag 不存在 → `INVALID_PARAMETER`/相应错误。
- [B] 超时与响应**同时到达**：必须恰好一个回复（验证 `DetachRequestLocked` + 定时器竞态）。
- [B] 无人等待时 response 到达 → 被丢弃（`DeliverResponse` 返回处理但不派发）。
- [B] 同一 `response_tag` 被不同 `request_tag` 复用 → `INVALID_PARAMETER`。
- [内存] 大量不同 `response_tag` 的请求完成后 `m_mapResponseOwner` 永不 erase → 趋势法 `XFAIL#G1`。
- [X] 请求方在等待中断开 → `CancelRequest` 清理；配合 fd 复用验证无错投。

### 7.8 持久化
- [N] 写入 BOARD/QUEUE → 正常 SIGTERM 重启 → 数据仍在（mmap 落盘）。
- [B] `kill -9` master+worker 后重启 → 校验文件未损坏、白盒不变量成立、队列读写指针自洽。
- [B] 建 tag 后崩溃，重启后该 tag 可读（或按实现确认半写情形）。
- [B] 启动时 `qbdfile/` 含损坏文件 → server 退出码 1（`gplat_load_qbd` 任一失败即退出）。

### 7.9 内存/泄漏
- [N] 基线：空闲实例 + 正常连接断开 + SIGTERM → 记录基线指纹（见第 5 节）。
- [B] 正常全量 CRUD 后 SIGTERM → 减基线后应**零残留**。
- [B] **带连接关闭**：客户端不 disconnect 直接被 server SIGTERM → 预期 shutdown-leak（`m_listPost`/recv/send 缓冲）→ 抑制并登记；取消抑制时应能复现，作为"修复后消失"的探针。
- [趋势/特征化] 连接 churn：断开即 `close(fd)`（fd 立即回收）但连接对象在回收队列滞留 `RecyWait` 秒；快速 churn 使 free-list 抽空 → `ngx_get_connection` `new` 新对象且**永不还 OS**，池按峰值在途连接撑大且不缩。**可靠门控**：churn 全程 worker fd 不随连接数膨胀、quiesce 后回基线（无 fd 泄漏）；池增长（M1）**仅特征化报告**（VmRSS 能否回落依赖 glibc `malloc_trim`，不适合作断言，故 M1 记为报告而非 XFAIL；每操作泄漏另由 ASan `mem.crud_no_residual` 作权威闸门）。

### 7.10 BOARD 频繁建删稳定性
- 随机种子驱动：N 轮 `{随机建 k 个 / 随机删 j 个 / 随机写读若干}`，每轮后跑**白盒校验器**全量不变量 + 影子模型比对。
- 专项：等字符和名字簇的建删（探测链压力）；删到空再建满；交替建删同名 tag（墓碑复用路径）。
- 并发变体：多连接并发建删同一 BOARD → `DeleteItem` 的 `memmove` 不持条带锁，与 `readb/writeb` 竞态 → 检测数据错乱/崩溃（ASan + fork，`XFAIL#B1`）。

### 7.11 连接 churn（高频短连接）
- 循环：`connectgplat → 单条命令（readb/writeb）→ disconnect`，统计 QPS、建连延迟分布。
- FIN vs RST：用 `SO_LINGER{on,0}` 制造 RST，对比服务端 `recvproc` 对 `EAGAIN/EINTR`、`RDHUP` 的处理（近期提交刚修过 EAGAIN/EINTR）。
- 资源泄漏：长时间 churn 期间趋势采样 worker 的 fd 数与 RSS；验证连接对象 20s 后回收、fd 立即关闭、无 fd 泄漏。
- 临界：临时端口耗尽前的高频建连（本机 ~28k 端口、`tcp_tw_reuse=2`）；**多进程客户端**分摊，使单进程 fd 不触及 1024（规避 `FD_SET` 栈溢出，该 bug 另由专项 [X] 覆盖）。
- [X] 单进程故意把客户端 fd 顶到 ≥1024 触发 `unblock_connect` 栈溢出 → fork + `XFAIL#C6`。

### 7.12 裸协议模糊（破坏性，默认不跑）
- 手工拼 `MSGHEAD`：未知/NULL MSGID（0–4、未注册）→ server 静默丢包、客户端应**超时而非挂死**（用例带超时）。
- `bodysize` 截断、`datasize != bodysize`、`e_pkgLen>16384`、非 NUL 结尾 qname 触发 `strcpy` 越界、`readtype` 队列路径堆溢出 → 全部 fork 隔离，逐条对应 `XFAIL#` 登记。

## 10. 规模目标与运行方式（本机 WSL2：12 核 / 可用 ~5.7GB / 端口 ~28k / somaxconn 4096）

| 维度 | 默认规模（可 `--scale` 调） | 判据 |
|---|---|---|
| 高 QPS 单连接 | 100k 次 writeb/readb 混合 | 全部 CRC 正确、无泄漏；打印 p50/p99/p999 |
| 高并发连接 | 200 并发连接 × 各 1k 操作 | 数据正确、fd/RSS 稳态；性能仅报告 |
| 连接 churn | 50k 次短连接 | 无 fd 泄漏、池按预期回收 |
| 建删 churn | 10k 轮随机建删 | 每轮白盒不变量成立 |

- 性能数字**不设绝对阈值**（随机负载 + 带种子重放），只作趋势/报告。
- 破坏性与基准各自独立 target，默认 `make test` 不含。
